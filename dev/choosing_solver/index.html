Choosing a solver

We choose a solver according to the structure of the loss and penalty and the operations available for each term. First, we consider coordinate descent when the loss has a supported model and the penalty separates over coordinates or groups.

Coordinate descent uses cached residuals or matrix products, so a coordinate step avoids a full gradient calculation. For example, a dense least-squares step costs $O(n)$ operations, compared with $O(np)$ for the full gradient. Passes over the active coordinates further reduce the work when the fitted coefficient vector is sparse.

A separable penalty alone does not give a coordinate descent implementation, since the loss must provide a model through cdmodel. We describe this interface in A coordinate descent model of your own, where a custom model supplies the coordinate derivatives and cache updates.

For a sequence of penalty levels, we use solve_path to reuse the preceding fit and screen coordinates at the new level. Furthermore, reweight!, LLA and refit! build reweighted estimators, local linear approximations and refits on the same engine.

Proximal gradient uses a gradient of the loss and a proximal step on the entire penalty. In particular, it handles the nuclear norm through singular-value thresholding, as in Low-rank regression. ADMM instead requires a proximal operator for each term, and can be used for the graphical lasso as in The graphical lasso by ADMM.

For a nonconvex penalty, the choice of starting point can affect the solution, and the method pages state the applicable convergence conditions. Note that a stopping flag alone does not establish a global minimum of a nonconvex problem.

Iterates and accuracy

SparseIterate represents individual coordinates, AtomIterate represents groups, and SymmetricSparseIterate represents a symmetric matrix. Dense arrays can be used where the solver and functions support them, as listed with the options in Calling the solvers.

Finally, choose an accuracy measure appropriate to the problem. Checking a solution explains how a duality gap bounds objective error and how coordinate residuals measure optimality when no gap is available.
