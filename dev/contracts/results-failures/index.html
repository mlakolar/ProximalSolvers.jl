Results, mutation and failures

converged reports the implemented criterion for the selected solver. Read its meaning together with the working-precision limits, the method's contract, and the independently evaluated residual when accuracy matters.

RES-01 Convergence, limits and certificates

Statement.

Meeting the implemented stopping criterion is not the same as holding an independently certified optimum. The solvers stop on three kinds of evidence:

The entrywise matrix lasso uses the same PGD/APG result flags, with the full-matrix scores and scale in STOP-03.

For PGD/APG, the products displayed in the stopping rows are formed in the working type T, not evaluated as unrounded real-number inequalities. In particular, STOP-04 specifies the finite-scale/finite-residual guards, the lower bound on the computed threshold and the strict product comparison for dedicated KKT checks; STOP-07 adds guards for the generic mapping check. A computed threshold can overflow to Inf. Thus converged = true does not guarantee that an independently divided normalized residual is below the unrounded tolerance, nor does it certify coefficient accuracy.

In the CD rows, h_k is the change of coordinate (or group) k in the pass and s the loss scale. In the first two rows the changes are computed from the solver's cached residual, and the flag does not say that this cache is close to y − Xx at the returned point (see The cached residual). In the scalar least-squares row, the comparison of a scaled change with the threshold is made between the computed values, in working precision, of CD-03, so a case whose exact values are equal can pass; "below" is that computed comparison.

Of the problems audited, only the square-root lasso carries a certificate, and that certificate has the assumptions stated in The certificate and Tightening and the uncertified stop. After an uncertified stop, the bounded fallback can certify the stopped point or return a point with a proved lower objective. It does not guarantee recovery at exact fits, and a final converged = false can still mean a nonoptimal exact fit. For the other solvers converged = true reports that the criterion of its row was met. Check the returned point with the independent KKT residual when the result matters.

Reaching a pass or iteration limit is not convergence. CD can return a finite nonconverged solution and logs a warning when converged = false; PGD and APG do not log a warning merely because maxiter was reached, and ProxNewton logs none for any stop (PN-01). Gap certificates are implemented only for square-root-lasso CD. Elsewhere gap = NaN means that a gap was not calculated, and does not mean the gap is zero. CD's kkt_checks = 0 is also a compatibility placeholder. CDQ-03 and CDQ-04 specify the certificate assumptions, tightening and uncertified stop. CDQ-05 specifies the fallback's returned point, pass total, restored or final-stage change statistics, and RNG advancement. The original criterion table above is interpreted with that later fallback qualification: an initial uncertified stop need not be the final result. A square-root certificate at an exact fit supplies no positive scaled-lasso noise-scale minimizer; see CDQ-06.

The PGD/APG rows use a product-threshold comparison in working precision. STOP-04 defines its formation and guards. The baseline's normalized-residual assertion is retained for provenance under Unreconciled.

For nonnegative least squares and nonnegative lasso, dense PGD uses the constrained residual in STOP-16, subject to the same computed-threshold guards in STOP-04. A kept stop is a working-precision stationarity check; it does not supply an exact-arithmetic certificate or a calculated duality gap. The supported inputs and feasibility refusals are in IN-07. With CDSolver on a dense Vector, these penalties use the change-test row of the table above: converged does not check the constrained KKT conditions, and the reported minimum is the objective from the cached residual (CD-09).

Uncentered SqrNormL2 ridge was also added after the table's baseline. Its scalar least-squares CD run uses the same full-pass change criterion as the first row, specified by CD-03, with passes counting completed passes, kkt_checks = 0 as a compatibility sentinel and gap = NaN. The result's minimizer is the caller's dense vector or owner, and minimum is the final finite objective evaluated from the cached least-squares residual plus the ridge penalty. CDS-03/CDS-04 retain the owner commit and propagated failure boundary; adding a ridge penalty supplies no duality certificate.

For consensus ADMM, ADM-02 specifies the computed residual tests, the stagnation guard, counters, limit statuses and numerical failure boundary. For the graphical lasso, ADM-04 replaces the stagnation score and adds the symmetry and Cholesky rules. For the least-squares lasso, ADM-05 replaces only the stagnation score. Graphical-lasso PGD uses the KKT check and result fields in PGD-08, with the rollback boundary in PGD-07.

RES-02 Gradient result fields and counters

Statement.

This clause describes OptimizationResults for PGD and APG with regression coefficients, including IN-10. See PGD-08 for graphical-lasso PGD. minimizer aliases the caller's coefficient storage and minimum is the reported objective at that iterate. iterations counts steps. iteration_converged reports reaching the iteration limit; it does not report successful convergence.

The result stores stopping flags, residuals and tolerances, an optional trace, oracle call counts and backtracking counts. x_converged, f_converged and grad_converged are the flags after the stationarity check, so all three are false when that check vetoed a proposed stop. Residual fields retain the last iteration's test residuals. APG's grad_calls includes one gradient at the accepted x for each stationarity check. PGD's backtrack_steps includes accepted nonzero line-search trials; APG counts every trial, including the accepted one. Detailed APG accounting is in APG-04.

f_increased records F > F_previous for the last computed objectives. An increase ends the solve only if allow_f_increases = false; the result does not store that option. f_residual is abs(F-F_previous)/abs(F), with 0.0 when both values are zero and Inf when F = 0 but the previous value is nonzero. With ftol > 0, this is the quantity compared with ftol. With ftol = 0, the objective test is off: f_tol = 0.0, f_converged = false, and f_residual is reported without deciding a stop. An iteration whose iterate equals the preceding one elementwise sets neither x_converged nor grad_converged under ftol = 0; STOP-10 also specifies the accelerated method's x == y case.

stagnated reports the specific Float32 PGD exit whose full condition, flags and scope are specified in STOP-11. Its x_residual is zero; it does not certify convergence or an accuracy target. Flags report independent conditions, so stagnated can coincide with call_limit_reached, iteration_converged, or an iteration whose callback returned true. STOP-09 specifies simultaneous flag combinations.

Applies to. OptimizationResults from PGD or APG, including nonconverged finite returns.

RES-03 Mutation and numerical failure boundaries

Statement.

Input validation completes before mutation; the alias rules are in IN-05. CD computes on private coefficient storage and commits only a finite completed run. Dense vectors therefore do not receive a partial numerical result. A caller's SparseIterate retains its original state when a numerical exception propagates out of solve!; a successful commit can remove active zeros and reorder slots. The RNG can still advance. The complete owner transaction is CDS-03/CDS-04; group and matrix owners use the specialized rules in CDG-08 and CDM-02.

Square-root CD can catch an ArgumentError inside a fallback stage and complete with the stopped point x0, as specified in CDQ-05. That finite completed result commits x0, which may differ from the caller's starting point. A propagated exception, including a nonfinite final objective, retains the outer transaction guarantee.

ProxNewton computes on private buffers and writes the caller's coefficients once, at a normal return; an exception from its inner coordinate solve or the logistic oracle leaves them unchanged (PN-05).

PGD and APG numerical step exceptions restore the last accepted coefficient point and rethrow. For IN-10 this restoration copies the full accepted coefficient matrix into the supplied storage. They do not provide a general transaction for internal counters or buffers. The line-search boundary is LS-09 and the accelerated trial/restart boundary is APG-03. A finite run that reaches a limit may still commit or return its point with converged = false; this is distinct from a thrown numerical error. Results share the mutable coefficient storage; copy it when retaining earlier coefficients. Extended traces copy coefficients and gradients.

Continue with Results and troubleshooting for reading a returned result, or the Glossary for terminology.

Applies to. Public solve wrappers; numerical exceptions and completed finite returns.

RES-UNRECONCILED Retired: historical normalized-residual guarantee

Retired by issue #416. The authoritative arithmetic and guards are STOP-04; RES-01 explains the result-flag interpretation.

Statement.

Original wording retained verbatim for provenance; not an active guarantee. The baseline OptimizationResults docstring said:

It is a working-precision value, not an exact-arithmetic certificate; it guarantees only that the computed, normalized residual ‖G‖∞ / max(λ, λmax) is below max(gradtol, 64 eps(T)) (the threshold is formed in T, see ProximalOptions), not coefficient accuracy on ill-conditioned designs.

That normalization statement does not generally follow from the implemented rounded product-threshold comparison and its underflow/overflow behavior. It was explicitly retired by #416 without changing solver behavior. The other original claims remain in STOP-UNRECONCILED, also retired. The caution about coefficient accuracy on ill-conditioned designs remains valid; the normalized inequality is not a public guarantee.

Applies to. Provenance of the baseline PGD/APG OptimizationResults documentation.

Code. src/types.jl: baseline OptimizationResults docstring; src/solve.jl and the stationarity helpers implement the product comparison.

Tests. No new test or behavior is claimed by this historical note; STOP-04 records the implementation and its existing coverage.
