Developer architecture

This page is for implementation contributors. Begin with Getting started and the input contract for package use, or the algorithm introduction for an explanation of the methods. These internal relationships do not create public extension APIs.

ARCH-01 Separate engines and shared gradient machinery

Statement.

The development core keeps coordinate descent separate from proximal gradient descent. Both least-squares engines support the lasso, weighted NormL1 and unweighted ElasticNet; the full dispatch matrix is IN-01. CD retains its own options and result type. PGD and APG share the least-squares image model, dense iterate/gradient buffers, gradient engine _solve_gradient!, stopping rules and OptimizationResults. APG adds its own extrapolation, restart state and line search. The separation is intentional; no untested common CD/gradient engine is introduced.

Small native helpers support the separately cached algorithms and existing result types. The source snapshot reconciled in issue #416 contains 15 .jl files: the src/ProximalSolvers.jl module; six shared files (types.jl, blocks.jl, line_searches.jl, solve.jl, utils.jl, precompile.jl); three gradient files under src/solvers/ (image_models.jl, proximal_gradient_descent.jl, accelerated_proximal_gradient_descent.jl); and five CD files under src/cd/ (models.jl, solver.jl, leastsquares.jl, multiresponse.jl, sqrtlasso.jl). This is a dated source inventory, not a permanent file-count guarantee. The superseded thirteen-file list is preserved as retired historical evidence.

ProximalBase supplies losses, L1 proximal operations and sparse coefficient storage; ProximalSolvers owns orchestration and algorithm-specific results. CD uses ProximalBase's scalar prox_block; PGD retains fused value_and_prox!. Ownership of least-squares value/gradient oracles and solver caches is specified once in FP-01. Dependency and diagnostic provenance is in HIST-03.

Applies to. The current source organization; internal relationships rather than extension guarantees.

Code. src/ProximalSolvers.jl; src/solve.jl; src/solvers/image_models.jl; the two gradient solver implementations and src/cd/.

Tests. test/minimal_core_characterization.jl, test/core_regressions.jl, test/accelerated_pgd.jl; implementation organization is also visible in the source tree.

ARCH-02 CD wrappers, owners and model-specific hooks

Statement.

Dense-vector and SparseIterate CD entry points run the same private model, state, passes, warning and finite-objective check on a ProximalBase SparseIterate. The dense wrapper builds that internal owner from the vector and scatters the completed result back. The owner wrapper uses copy, then commits with same-shape copyto! through ProximalBase's public storage methods after the finite-objective check; it does not rebuild the owner through a dense vector. Initial/final slot state, compaction and failure atomicity are specified by CDS-02 through CDS-04. Validation separates shared data checks from an owner gate that inspects public active values and checks aliasing against the original owner. PGD retains the dense gate and refuses these owners.

Group CD uses the same engine on a ProximalBase BlockIterate, treating groups as coordinates. Its private BlockLSModel wraps the scalar least-squares model's data, residual and column kernels, and adds a curvature bound per group, stored as NaN while uncomputed. _prepare! runs after residual initialization and before the first pass when maxpasses > 0; the scalar model's default _prepare! is a no-op. The complete curvature/step refusal timing, cheap Gram bounds, deferred eigenvalue work, closed-form two-column route and zero-block screen are defined in CDG-03 through CDG-06. A group update uses prox_block! on a compact scratch vector. Pass scheduling, the group change statistic and the private-copy transaction are the scalar engine's corresponding mechanisms with group-specific rules in CDG-07 and CDG-08.

Square-root-lasso CD uses the SparseIterate engine with a private SqrtLSModel. It wraps the least-squares model at loss scale one (data, residual, curvature cache, residual updates and stopping scales) and supplies its own coordinate step. A unsmoothed full-pass change stop calls _stop_check!, returning :converged, :uncertified, or :retry; the retry lowers the threshold, which the loop reads again. The generic hook returns the constant :converged, preserving the least-squares and group change tests. The square-root model performs its duality certificate there and records the certified bound in gap; CDQ-03 and CDQ-04 specify the numerical rules. After a terminal uncertified stop, _run_cd! invokes the model's _fallback! before issuing the warning and checking the final objective. That hook is a no-op for models without a certificate. The square-root model supplies the bounded smoothing continuation in CDQ-05, whose smoothed stages use the same private engine and whose original-objective bounds decide the returned point. The outer wrappers still commit only after a finite completed run.

Applies to. Private CD engines, wrappers and model hooks.

Code. src/cd/models.jl; src/cd/solver.jl: _run_cd!, _prepare!, _stop_check!; src/cd/leastsquares.jl: model implementations; src/solve.jl: wrappers.

Tests. test/sparse_cd.jl, test/group_cd.jl, test/group_cd_preflight.jl, test/multiresponse_cd.jl, test/sqrt_lasso.jl.

Sources. docs/src/internals.md:L13, docs/src/internals.md:L23, docs/src/internals.md:L48, docs/src/developer/implementation-notes.md:L442. The later fallback seam is f573224f, the generic model hook and the private run boundary.

ARCH-03 Private seams and public support boundaries

Statement.

CDModel and state hooks are private extraction and test seams. Their existence does not promise support for custom losses or public workspaces. Generic block, metric, certificate and logging frameworks remain deferred under DEF-01. The private ProximalBase SparseIterate contract remains unchanged; the historical group/workspace migration in PR #237 is not imported. Public supported combinations, validation and transaction boundaries are in the contract pages, not inferred from private implementation dispatch.

Historical platform and performance records, dependency pins and paired-analysis provenance are kept in HIST-03 and HIST-04. Contributor workflow and CI policy remain governed by the repository's contributor guidance.

Applies to. Contributor use of private models/state and the development core support boundary.

Code. src/cd/models.jl, src/cd/solver.jl, public src/solve.jl gates.

Tests. test/core_contracts.jl and private-seam characterization tests; no extension API is claimed by those tests.

Sources. docs/src/internals.md:L62, docs/src/developer/implementation-notes.md:L434, docs/src/developer/implementation-notes.md:L456.
