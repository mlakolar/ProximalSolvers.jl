Coordinate descent reference

Square-root losses

ProximalSolvers.SqrtLeastSquaresLoss — Type
SqrtLeastSquaresLoss(y, X; weights = nothing)

The loss f(β) = ‖y - Xβ‖₂ of the square-root lasso (Belloni, Chernozhukov and Wang, 2011), whose optimal penalty level does not depend on the noise level, or with observation weights w ≥ 0 the weighted norm √(∑ᵢ wᵢ (yᵢ - Xᵢ'β)²). It is not differentiable where the residuals vanish, so coordinate descent (CDSolver) minimizes f + g exactly over each coordinate, which it does for g = NormL1(λ, w). With cdmodel(f, x; intercept = true) the loss is minimized over an unpenalized intercept as well.

source
ProximalSolvers.SqrtQuadraticFunction — Type
SqrtQuadraticFunction(A, b, c; check = true)

The loss f(x) = √(x'Ax + 2b'x + c), with symmetric positive semidefinite A and a nonnegative quadratic: with A = X'X/n, b = -X'y/n and c = y'y/n it is ‖y - Xx‖ / √n, the loss of SqrtLeastSquaresLoss divided by √n, from the sufficient statistics. Coordinate descent (CDSolver) minimizes f + g exactly over each coordinate, for g = NormL1(λ, w), at a cost of O(p) per update instead of O(n). With A = S, b = -S[:, j], c = S[j, j] and an infinite weight on coordinate j, it is the square-root (scaled) lasso of variable j on the others from their covariance matrix S, as in the precision matrix estimator of Sun and Zhang (2013).

A dense Matrix A is used as it is, any other matrix is copied into one. With check, A must be finite and symmetric, which costs O(p²); pass check = false when many losses share one A checked once, as the columns of a covariance matrix do. b and c are always checked.

Penalty levels and paths

ProximalSolvers.lambda_max — Function
lambda_max(f, g, x)

The smallest penalty level λ for which zero minimizes f + g with the level of g replaced by λ (NormL1(λ, w) for g = NormL1(λ0, w), and so on): maxₖ |∇ₖf(0)| / wₖ over the coordinates of iterates like x whose weight is not zero, with ‖∇_G f(0)‖₂ for the groups of a GroupNormL2. The level of Scaled(ElasticNet(α, 1 - α, w), λ) is its scale λ, and its weights are α wₖ. So is the level of the sparse group lasso at a fixed mixture, Scaled(SparseGroupNormL2(α, 1 - α, groups, w), λ): group G is zero at the level λ when ‖soft(∇_G f(0), αλ)‖₂ ≤ (1 - α)λ w_G, and λmax is the largest of the levels at which this starts to hold, each the exact root of a quadratic. On a box, Constrained(g, IndBox(l, u)) with l ≤ 0 ≤ u, only the part of the gradient that points into the box counts: (-∇ₖf(0))₊ when uₖ > 0 and (∇ₖf(0))₊ when lₖ < 0, so that λmax of the nonnegative lasso, Constrained(NormL1(λ), IndBox(0, Inf)), is maxₖ (-∇ₖf(0))₊ / wₖ.

CappedL1(λ, a, w) and LogPenalty(λ, ε, w) have paths by LLA only, and their λmax is that of the first stage, the lasso with the slopes at zero: the weights wₖ and wₖ/ε. Zero is then a stationary point of f + g, and the first stage of LLA from zero stays there.

source
lambda_max(f, g::SLOPE, x::Vector)

For single-response least squares, optionally scaled, return the smallest multiplier of the SLOPE weights making zero optimal: the maximum of the sorted absolute null-gradient prefix sums divided by the weight prefix sums. x supplies the coefficient type and dimensions and is not modified. All-zero weights give Inf unless the null gradient is zero, in which case the result is zero. This is an optimization threshold, with no statistical calibration.

ProximalSolvers.solve_path — Function
solve_path(f, g, λs, method::ProxNewton; x, screening = true, maxnnz = Inf, callback = nothing, devmax = 0.999,
           gaptol)

The path of ProxNewton solutions along the decreasing levels λs, for a GLMLoss f or its model with an intercept (cdmodel(f, x; intercept = true)), as solve_path computes it for coordinate descent: each level is warm started from the previous solution and its intercept, with the sequential strong rule and checks of the optimality conditions when screening, and the path stops after more than maxnnz nonzero coordinates or when callback(k, λ, x, m) returns true. With an intercept, the starting intercept is fitted to the starting x (zero by default), so that the first level can be λmax from lambda_max of the same model.

The path also stops once the fraction of the null deviance that the fit explains, 1 - D/D₀, reaches devmax, as glmnet's does: D is the deviance 2 ∑ᵢ wᵢ (ℓ(ηᵢ, yᵢ) - minᵤ ℓ(u, yᵢ)) and D₀ that of the fit with β = 0. Along a logistic path on separable data the coefficients grow without bound, and the explained fraction tends to one. devmax = 1 never stops; the rule is off for a scalar loss whose saturated loss is unknown.

As for coordinate descent, each level stops on a relative duality gap of at most gaptol (PATH_GAPTOL = 1e-4 by default, 1e-3 for the faster setting) when the loss and the penalty have one (the squared, logistic, Poisson and Huber losses with NormL1, NormL1Nonneg or ElasticNet): the Newton steps stop on the gap of the problem restricted to the candidates, each inner solve stops on the gap of its quadratic model at a hundredth of the last gap, and the full gradient of the optimality check confirms the gap of the whole problem, which the gap of the results reports. With an intercept, the intercept is fitted exactly before each gap. gaptol = 0, and the other penalties (MCP, SCAD, …), keep the rule on the change of the objective with method.tol and the inner solver's own rule.

source
solve_path(f, g, λs, method = CDSolver(); x, screening = true, maxnnz = Inf, callback = nothing, gaptol)

Minimize f + gₖ along the decreasing penalty levels λs, where gₖ is g with level λs[k], each warm started from the previous solution. The level of ElasticNet(λ1, λ2, w) is λ1, with λ2 fixed; for glmnet's elastic-net path at a fixed α, λ(α ∑ᵢ wᵢ|xᵢ| + (1 - α)‖x‖²/2), take g = Scaled(ElasticNet(α, 1 - α, w), 1), whose level is the scale; for the sparse group lasso path of R's SGL and sparsegl, λ(α‖x‖₁ + (1 - α)Σₖ wₖ‖x_Gₖ‖₂), take g = Scaled(SparseGroupNormL2(α, 1 - α, groups, w), 1) and x = AtomIterate(p, groups). The iterate x (a zero SparseIterate of the right length when f has columns, which must otherwise be given) is the starting point and holds the last solution on return.

With screening, each level is solved first over the coordinates kept by the sequential strong rule of Tibshirani et al. (2012), and the optimality conditions of the others are checked afterwards; violators are added and the problem solved again. The path stops early after the first solution with more than maxnnz nonzero coordinates, or when callback(k, λ, x, m) returns true (m is the CDModel, current for x; use it, for example, to compute a validation loss). Returns PathResults.

Each level stops on a certified relative duality gap, (P - D)/|P| ≤ gaptol with P = f + gₖ at the solution and D the dual objective at the dual point built from the gradient (see duality_gap), when f and g have a gap: least squares and the GLMs with the squared, logistic, Poisson or Huber loss, with NormL1, NormL1Nonneg, ElasticNet, GroupNormL2 or the sparse group lasso. The default gaptol is PATH_GAPTOL = 1e-4 (or method.gaptol when it is positive); gaptol = 1e-3 is the faster setting for cross-validation and prediction. During the solve the gap is that of the problem restricted to the candidates of the strong rule, at the cost of one pass over them; the full gradient of the optimality check of screening then gives the gap of the whole problem, which the gap of the results reports. A relative gap ε certifies a relative suboptimality of at most ε; in practice the suboptimality is about ε², since this gap shrinks only as fast as the error of the fitted values, and the coefficients are within about ε of the solution, relative to the largest (median over the levels), and within about 50ε at worst: about 1e-4 (worst 5e-3) at the default and 1e-3 (worst 2e-2) at 1e-3, well below the statistical error of most fits. Other losses and penalties, a coordinate without penalty whose gradient is not zero (whose dual point does not exist), and gaptol = 0 keep the rule on the changes of CDSolver with its tol, which reaches relative suboptimalities of 1e-11 to 1e-16 on least squares.

The slope test at zero, on which λmax and screening rest, agrees with the exact coordinate steps of MCP(λ, a), SCAD(λ, a), GroupMCP and GroupSCAD only when each coordinate problem is convex: a·Lₖ > 1 for MCP and (a - 1)·Lₖ > 1 for SCAD, where Lₖ is the curvature of the step along coordinate k (of group k, for a group penalty). A path, and continuation, with these penalties throws an ArgumentError when a penalized coordinate fails it. For least squares, standardized columns give Lₖ = 1 with the loss ‖y - Xβ‖²/(2n), so that ncvreg's conditions a > 1 and a > 2 suffice. The path of LLA, solve_path(f, g, λs, LLA()), has no such condition.

source
solve_path(f, g, λs, method::LLA; x, screening = true, maxnnz = Inf, callback = nothing)

The path of local linear approximation (see LLA) along the decreasing levels λs, for g a CappedL1, LogPenalty, MCP, SCAD, GroupMCP or GroupSCAD of ProximalBase, whose level is λ (for LogPenalty(λ, ε), the slope at zero is λ/ε). At each level the stages of method run; with start = :lasso the first stage is the lasso with the weights pⱼ′(0), warm started from the lasso at the previous level, and with start = :previous it takes its weights from the solution at the previous level and starts from it. The later stages start from the stage before.

Every stage is a weighted lasso (a weighted group lasso for a group penalty), convex, so its screening is exact: with screening, the first stage uses the sequential strong rule for the step from the previous level, and the later stages the coordinates that are nonzero or violate their optimality condition at the previous stage; the optimality conditions of the others are checked after each stage, as for solve_path with CDSolver, and the gap-safe rule of CDSolver(; gapsafe = true) applies inside the stages that have a duality gap. The first level of a grid is usually lambda_max(f, g, x), the level of the first stage. The path stops early after the first solution with more than maxnnz nonzero coordinates, or when callback(k, λ, x, m) returns true.

Returns PathResults: its values are the loss plus g at each level, the passes and checks are summed over the stages, converged says whether coordinate descent converged in every stage, and stages gives the number of stages at each level.

source
solve_path(f, g::SLOPE, factors, method::SLOPEAPG; x, screening=true)

Solve single-response least-squares problems f + factors[k]*g by screened APG. factors must be positive, finite and nonincreasing. x defaults to a dense zero vector and holds the last solution on return; saved solutions do not alias it. Screening always includes the current support and repairs violations using the full SLOPE proximal fixed-point equation. screening=false fits all columns. The caller supplies already prepared data and penalty weights. See SLOPEAPG for the residual and per-level iteration budget.

source
ProximalSolvers.PathResults — Type
PathResults

Returned by solve_path: the penalty levels λ that were solved for, the solutions (a SparseVector per level for a vector iterate, a sparse matrix for a matrix iterate), the objective values, and per level the passes, whether coordinate descent converged, the number of kkt_checks of the screening, the number of stages (1, except along a path of LLA, where the passes and the checks are summed over the stages), and the relative duality gap certified at each level when the levels stop on the gap (see gaptol in solve_path), NaN where they stop on the rule on the changes.

source
ProximalSolvers.PATH_GAPTOL — Constant
PATH_GAPTOL = 1e-4

The default target of the relative duality gap at each level of solve_path and at the last level of continuation; see solve_path. The coefficients are then within about 1e-4 of the solution, relative to the largest, and within about 5e-3 at worst. gaptol = 1e-3 is the documented faster setting, for cross-validation and prediction, and gaptol = 0 gives back the rule on the changes.

source
ProximalSolvers.LLA — Type
LLA(inner = CDSolver(); stages = 2, tol = 1e-12, start = :lasso)

Local linear approximation (LLA), also called reweighted ℓ1, for the nonconvex penalties CappedL1, LogPenalty, MCP, SCAD, GroupMCP and GroupSCAD of ProximalBase, with the penalty as defined (a fixed cap, a fixed ε, a fixed a). Each stage minimizes the loss plus the tangent of the penalty at the previous solution: the weighted lasso with the weights pⱼ′(|xⱼ|) of ProximalBase.lla_weights!, or the weighted group lasso with pₖ′(‖x_Gₖ‖₂) for a group penalty. Each stage is convex and is solved by inner; alternating stages and weights decreases the loss plus the penalty (majorization-minimization).

  • stages: the most stages at a level, the first one included. The stages stop early once the weights change by at most tol, relative to the largest weight; the default tol is rounding, so that a stage is skipped only when it would repeat the last one. The default, two stages from zero, is the lasso followed by one weighted lasso: the two-step estimator of Fan, Xue and Zou (2014). A large stages, such as 100, with tol iterates until the weights stop changing, as do the multi-stage convex relaxation of T. Zhang (2010), the difference of convex functions of Shen, Pan and Zhu (2012) and the reweighted ℓ1 of Candès, Wakin and Boyd (2008). For CappedL1 the weights take finitely many values, and the default tol stops when they repeat.
  • start: where the first stage of a level of solve_path takes its weights. With :lasso, the default, from zero, so that the first stage is the lasso with the weights pⱼ′(0) and every level starts again from it, as the papers do. With :previous, from the solution at the previous level, which follows the path more cheaply.

solve_path(f, g, λs, LLA()) gives the path, and solve!(x, f, g, LLA()) one level, with the first weights at x: from zero the first stage is the lasso, and from an initial estimate one stage is the one-step estimator of Zou and Li (2008).

Reweighting and refits

ProximalSolvers.reweight! — Function
reweight!(x, f, g, update, method = CDSolver(); maxiter = 20, tol = 1e-2)

Alternate between minimizing f + g over x, warm started from the previous solution, and updating the penalty: update(g, x, m) returns the next penalty and the relative change that it makes, from the solution x and the CDModel m, which is current for x (its residuals, gradient, …). Stops when the change is below tol, or after maxiter solves. Returns ReweightResults.

This covers the iterative lasso procedures: the scaled lasso (the level λσ̂ with σ̂ = ‖r‖/√n from the residuals) and the lasso with data-driven penalty loadings. update follows every solve, the last one included, which gives converged and next. A two-stage estimator, which recomputes its weights once at a first solution, can use maxiter = 2, tol = 0 when the weights are cheap. When they are not, it solves twice with one model (m = cdmodel(f, x), then solve!(x, m, g, method) for each penalty), which computes them once.

source
ProximalSolvers.ReweightResults — Type
ReweightResults

Returned by reweight!: the minimizer x, the penalty at which it was computed, the next penalty that update proposed from it, the number of outer iterations, whether the relative change fell below the tolerance (converged), and the coordinate descent passes summed over the solves, with whether every solve cd_converged.

ProximalSolvers.refit! — Function
refit!(x, f; support, cache = nothing)

Overwrite x with the minimizer of the loss f over the iterates supported on support, the nonzero coordinates of x unless given: the refit after a penalized fit, for least squares and the other quadratic losses (a model supports it if its coordinates are those of a quadratic, as for LeastSquaresLoss, a least-squares GLMLoss, QuadraticFunction and KronQuadratic). Least squares solves the least-squares problem on the columns of the support by a pivoted QR factorization, and the others the linear system of the Hessian on the support; when the minimizer is not unique, a solution of the rank-deficient system. Returns x.

With a RefitCache, least squares and QuadraticFunction keep the Cholesky factor of the Hessian on the support between calls and update it when the support changes, which makes refits along a path of supports much cheaper.

source
ProximalSolvers.RefitCache — Type
RefitCache(T = Float64)

The Cholesky factor of the Hessian of a quadratic loss on a support, which refit! keeps between calls with refit!(x, f; support, cache). A later refit of the same f on a support that differs by a few coordinates updates the factor instead of computing it again:

  • a coordinate that enters borders it, in O(n|S| + |S|²) for least squares;
  • one that leaves is removed by Givens rotations, in O(|S|²).

So refits along a path of supports, as after a lasso path, cost about as much as the gradient on the support, instead of O(n|S|²) each. When many coordinates change, it is cheaper to factor again, which the cache then does.

It serves least squares (LeastSquaresLoss, a least-squares GLMLoss, either scaled) and QuadraticFunction; for other losses the cache is ignored. When an entering coordinate is nearly a combination of the others (a new pivot below √eps of its curvature), the refit falls back to the pivoted QR factorization that refit! uses without a cache, which also handles a rank-deficient support, and the cache starts over.

The factor belongs to one loss: pass the same f (or the same model) to every refit, don't change its data in between, and don't share the cache between threads. refactors and updates count the factorizations from scratch and the coordinates added or removed by updates.

Models and their interface

ProximalSolvers.CDModel — Type
CDModel{T}

A loss together with the cache that makes its coordinate updates cheap, such as the residuals of least squares. cdmodel builds one from a loss of ProximalBase; solve! accepts a model in place of the loss, so that a model built once serves many solves (paths, reweighting).

A new model

A new loss is a subtype of CDModel{T} with these functions for the iterates it supports. They are public but not exported: extend them as ProximalSolvers.initialize! and so on.

  • initialize!(m, x), which makes the cache current for x.
  • The coordinate step: either coordinate_derivatives and update_cache!, from which coordinate descent takes a proximal step, or the whole step, coordinate_step!.

Optional:

  • coordinate_scale and response_scale, the scales of the relative stopping rule. Without them the rule is absolute.
  • loss_value, the value of the loss from the cache. The results report it, and Anderson acceleration needs it.
  • gradient!(G, m, x), the gradient at x from the cache, as an array of the size of x (one entry per entry of x, also for a SymmetricSparseIterate). lambda_max, screening, continuation and solve_path need it.
  • check_penalty, for a model that takes only some penalties.

Group penalties (GroupNormL2, GroupNormLinf and the other group norms of ProximalBase, on an AtomIterate) work with the built-in least-squares and quadratic models only. Momentum (see CDSolver) calls initialize! at each extrapolated point of a new model.

source
ProximalSolvers.cdmodel — Function
cdmodel(f, x)

The CDModel of the loss f for iterates like x: for LeastSquaresLoss, a least-squares GLMLoss (with weights and an offset), LeastSquaresLoss with a matrix Y (the multi-response lasso: x an AtomIterate over vec(B) with the rows of B as groups, [k:p:p*q for k in 1:p], and GroupNormL2 on them), QuadraticFunction and KronQuadratic, each possibly scaled, as in (1/n) * LeastSquaresLoss(y, X), for a logistic or Huber GLMLoss, and for SqrtLeastSquaresLoss and SqrtQuadraticFunction.

intercept(m::CDModel, x)

The unpenalized intercept that goes with x in a least-squares model built with intercept = true (see cdmodel); zero without one. For the multi-response model of a matrix Y, the vector of the intercepts of the responses.

ProximalSolvers.coordinate_derivatives — Function
coordinate_derivatives(m::CDModel, x, k) -> (G, a)

The derivative G of the loss along coordinate k of x and its curvature a, exact for a quadratic and otherwise an upper bound, from the cache of m. The default coordinate_step! moves the coordinate to prox_entry(g, xₖ - G/a, i, μ/a), where i is the index of the entry in x and μ the number of entries the coordinate sets (2 for an off-diagonal coordinate of a SymmetricSparseIterate). The step is exact for a quadratic loss, and a majorization step when a bounds the curvature.

source
ProximalSolvers.update_cache! — Function
update_cache!(m::CDModel, x, k, h)

Update the cache of m for the change h of coordinate k, which is already written into x.

source
ProximalSolvers.coordinate_step! — Function
coordinate_step!(m::CDModel, g, x, k) -> h

Move coordinate k of x to decrease the loss plus the penalty g, update the cache of m, and return the change of the coordinate. The default takes the proximal step from coordinate_derivatives and update_cache!. A model can define it to fuse the computations, as the built-in models do.

source
ProximalSolvers.coordinate_scale — Function
coordinate_scale(m::CDModel, x, k)

The scale by which the relative stopping rule of CDSolver multiplies the change of coordinate k: the square root of the curvature along it, such as ‖X[:, k]‖ √s for s ‖y - Xβ‖² / 2. Defaults to 1.

source
ProximalSolvers.response_scale — Function
response_scale(m::CDModel, x)

The scale by which the relative stopping rule of CDSolver multiplies tol, such as ‖y‖ √s for s ‖y - Xβ‖² / 2. It defaults to zero, which makes the rule absolute.

source
ProximalSolvers.loss_value — Function
loss_value(m::CDModel, x)

The value of the loss at x, from the cache of m. Defaults to NaN.

source
ProximalSolvers.check_penalty — Function
check_penalty(m::CDModel, g)

Throw an ArgumentError when the model m cannot take the penalty g. By default a model takes every penalty.
