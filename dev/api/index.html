API reference

This is the complete callable reference, including some historical constructor keywords that intentionally reject unsupported features. For practical options, see Choosing a solver; for deferred keyword combinations, see Supported problems.

ProximalGradientDescent() provides its supported backtracking line search by default. The qualified type ProximalSolvers.LineSearches.BackTracking appears below for API completeness. Ordinary users do not need to import or instantiate it separately.

ProximalSolvers.CDSolver — Type
CDSolver(; maxpasses=100_000, tol=1e-7, order=:random, relative=true,
           momentum=nothing, rng=Random.default_rng(), anderson=0,
           gaptol=0, gapsafe=false)

Coordinate descent for dense Float32/Float64 least-squares lasso (including weights), elastic net, ridge, group lasso and square-root lasso. Use a dense vector or one-dimensional SparseIterate for scalar problems, a BlockIterate for groups, or matrix coefficients for row-group multi-response regression. solve! updates the supplied coefficients. For deterministic scalar examples, choose order=:cyclic, momentum=false.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                CDSolver(order=:cyclic, momentum=false))

converged is a change test, with an additional certificate for square-root lasso; see result semantics.

Keywords

  • maxpasses=100_000: maximum number of coordinate passes.
  • tol=1e-7: change tolerance; it is not an independent accuracy target.
  • order=:random: random coordinate order; :cyclic is deterministic.
  • relative=true: scale the change test using the response and coordinate curvature; false uses an absolute change threshold.
  • momentum=nothing: use the algorithm's default momentum policy. false disables momentum. true is unsupported for cyclic order and group problems.
  • rng=Random.default_rng(): borrowed random generator, advanced when used. Create a fresh seeded generator to reproduce a random order.
  • anderson=0: reserved Anderson-acceleration setting; only 0 is accepted.
  • gaptol=0: reserved dual-gap stopping target; only 0 is accepted.
  • gapsafe=false: reserved gap-safe screening switch; only false is accepted. These three compatibility settings are not stored or used.

Extended help

The data arrays share one Float32 or Float64 element type. With least squares, use NormL1(lambda), NormL1(lambda, w), an unweighted ElasticNet or an uncentered SqrNormL2(lambda) for scalar coefficients. Ridge via SqrNormL2 is supported only by CD, for dense vectors or one-dimensional SparseIterate; a centered penalty is refused, even with an all-zero center. Weights must be a matching Vector{T} satisfying the validated coefficient-range rules; a zero weight leaves its coordinate unpenalized. Group penalties require matching partitions; matrix-response groups are the rows of the coefficient matrix, indexed through vec(B).

Square-root lasso requires an unscaled SqrtLeastSquaresLoss and unweighted NormL1(lambda) with lambda > 0. For the normalized square-root objective, use lambda = sqrt(n)*lambda_n in this unnormalized interface. For a positive minimum, converged=true proves a relative objective error of at most 1e-4. The certificate bound is rounded upward to the working type T for gap, so its stored Float32 value can be slightly above 1e-4. After an uncertified change-test stop, a bounded smoothing fallback can certify the stopped point or return a point with a proved lower objective. It uses the remaining maxpasses budget and the solver's order, momentum, RNG and tolerances; its passes count in the result and its random passes advance the borrowed RNG. A run that reaches maxpasses does not start this fallback. Recovery at exact fits is not guaranteed: a final uncertified result has converged=false, gap=NaN and a warning. See the bounded square-root fallback.

CD commits coefficients only after a completed run with a finite objective. An exception escaping solve! preserves the caller's starting coefficients, although a borrowed RNG may have advanced. After a successful sparse/group solve, obtain fresh active-coordinate/value views because compaction can change the storage.

Detailed rules:

  • Sparse storage and commit semantics.
  • Group steps, curvature and refusals.
  • Multi-response shapes and row groups.
  • Square-root steps and bounded certificate.

See solve! and the solver guide.

ProximalSolvers.ProximalGradientDescent — Type
ProximalGradientDescent(; ls=LineSearches.BackTracking(), normalized=false,
                         debias=0, preconditioner=:none)

Proximal gradient descent for least squares with NormL1 (optionally weighted), unweighted ElasticNet, NormLinf, GroupNormL2, unweighted NormL1Nonneg or IndNonnegative(). Coefficients are a dense Vector{Float32} or Vector{Float64} with same-type dense data. Each iteration combines a smooth-loss gradient step with the penalty's proximal operator, using backtracking. Pass ProximalOptions as the fifth argument to solve! for stopping and tracing.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                ProximalGradientDescent())

converged is a computed stopping decision, not a coefficient-accuracy promise; see the stopping contract.

Extended help

ls must be LineSearches.BackTracking; custom line searches are unsupported. The compatibility keywords normalized=false, debias=0 and preconditioner=:none are accepted only at their defaults and are not stored. PGD requires dense coefficients and refuses SparseIterate, BlockIterate, matrix responses and square-root loss. A group penalty must have the same parameter type as the data and groups partitioning the coefficients.

For nonnegative least squares, use IndNonnegative() or NormL1Nonneg(0). For nonnegative lasso, use unweighted NormL1Nonneg(lambda) with a positive level. Both require a nonnegative starting vector. Infeasible starts are refused before writes, and the proximal step preserves feasibility. The level must be finite, nonnegative and representable in the working type. Weighted NormL1Nonneg is unsupported, including an all-ones weight vector. This penalty is supported only by PGD. See the input contract.

A stopping proposal from the iterate, objective or gradient test must pass the applicable stationarity check. NormL1, ElasticNet, GroupNormL2, NormL1Nonneg, and IndNonnegative() have KKT checks; the nonnegative case uses the constrained scores at positive and zero coefficients specified by STOP-16. Use IndBox or IndBallLinf for box constraints and IndBallL2 for a four-coefficient Euclidean ball with a same-type radius. These indicators require a feasible start and use the generic proximal-gradient check, as does NormLinf. Assess fits with an independent diagnostic, particularly for Float32 or ill-conditioned designs. An error in an iteration restores the last accepted coefficient vector and is rethrown.

  • Backtracking and numerical range limits.
  • Stopping criteria and result interpretation.

ProximalSolvers.AccProxGradDescent — Type
AccProxGradDescent(; β = 0.5, α = 0.9, preconditioner = :none)

Accelerated proximal gradient descent for dense Float32/Float64 least squares with NormL1 (optional weights), unweighted ElasticNet, NormLinf or GroupNormL2. It extrapolates from previous accepted iterates, takes a backtracked proximal step, and restarts momentum on an objective increase. Pass ProximalOptions as the fifth argument to solve!; the result and stopping interface are shared with PGD.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                AccProxGradDescent())

converged reports the computed stopping criterion, not coefficient accuracy; see the stopping contract.

Extended help

  • β=0.5: factor shrinking the step after a rejected trial; 0 < β < 1.
  • α=0.9: factor reducing curvature before each iteration; 0 < α <= 1. At α=1 this adjustment does not grow the step.
  • preconditioner=:none: only supported value; other choices are rejected.

Parameter bounds must also hold after conversion to the working type, and additional dimension bounds apply. The extrapolation weight is k/(k+3), counting from the start or last restart; this is not the textbook FISTA recurrence. A restart repeats the step without momentum. An error in backtracking restores the last accepted coefficient vector and is rethrown.

The supported penalties are NormL1 with optional weights, unweighted ElasticNet, NormLinf and a matching GroupNormL2{T} on dense coefficients. Box constraints use IndBox or IndBallLinf. Euclidean-ball constraints use IndBallL2 with four coefficients and a radius of the same type. These indicators require a feasible starting vector. Use ProximalGradientDescent for unweighted NormL1Nonneg; APG does not support that constrained penalty. A proposed stop is checked at the accepted point. The iteration's reported gradient-mapping residual is measured from the extrapolated point, so use the stopping documentation when interpreting it. The extra gradient for a proposed stop is included in grad_calls.

  • Extrapolation, restarts and dimension limits.
  • Certified local bound test and assumptions.
  • Shared stopping and exceptional exits.

ProximalSolvers.ADMMSolver — Type
ADMMSolver(; ρ=1.0, α=1.0, abstol=1e-6, reltol=1e-4, abstol_dual=abstol, adaptive=false)

Solve SqrNormL2(λ, c) + NormL1(τ) by scaled consensus ADMM on a dense Vector{Float32} or Vector{Float64} with a same-type center c. ρ is the positive penalty and α ∈ (0, 2) controls relaxation. The absolute and relative tolerances control the primal and dual residual tests. Set adaptive=true to rebalance the penalty between iterations.

See the ADMM contract for the supported inputs and iteration rules.

ProximalSolvers.solve! — Function
solve!(x, f, g, CDSolver())
solve!(x, f, g, ProximalGradientDescent(), options=ProximalOptions())
solve!(x, f, g, AccProxGradDescent(), options=ProximalOptions())
solve!(x::BlockIterate, f, g::GroupNormL2, CDSolver())

Minimize a supported penalized regression objective, overwriting x, and return a result whose minimizer is that coefficient storage. Use matching Float32/Float64 data and coefficients. CD additionally accepts sparse/group iterate storage and row-group matrix-response problems; PGD and APG require a dense coefficient vector. Choose a method and penalty from the support matrix.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                CDSolver(order=:cyclic, momentum=false))
saved_beta = copy(result.minimizer)

The meaning of converged depends on the method and loss; see result semantics.

Extended help

LeastSquaresLoss is half the sum of squared residuals. Multiply by 1/n for the conventional normalized lasso. One supported positive scalar loss wrapper is accepted. Penalty levels and weights must meet the relevant input rules; a zero weight leaves its coefficient or group unpenalized.

Do not modify data during a solve, or alias x with the data, penalty weights or other disallowed mutable storage. Results share x; copying the result object alone does not preserve earlier coefficients.

An exception escaping a CD solve leaves the caller's original coefficients unchanged; a completed finite run, including a pass-limit outcome, commits its final point. PGD/APG iteration errors restore the last accepted point and rethrow. Internal counters have no transaction guarantee. A borrowed CD RNG may have advanced when a numerical failure occurs during a pass. After a successful sparse/group solve, reacquire active-coordinate/value views because its active storage can change.

Ridge via uncentered SqrNormL2(lambda) is supported with least squares and CD on a dense vector or one-dimensional SparseIterate. Its penalty is (lambda/2) * sum(abs2, x); lambda must be finite, nonnegative and representable in the coefficient type. Centered penalties, including an all-zero center, and this penalty with PGD, APG, block/matrix coefficients or square-root loss are refused. See supported inputs.

Group CD requires a BlockIterate with the penalty's ordered groups; group PGD/APG require a same-type GroupNormL2{T} and dense coefficients. Square-root lasso is available only with CD, an unscaled loss and an unweighted positive L1 level; its successful stopping flag requires a certificate.

Use IndNonnegative() or NormL1Nonneg(0) for nonnegative least squares and unweighted NormL1Nonneg(lambda) for nonnegative lasso. These penalties require PGD, dense same-type least-squares data and a nonnegative starting vector. An infeasible start is refused before writes. The stopping check uses the constrained KKT residual and the lasso's symmetric gradient scale. See inputs and stopping.

  • Supported inputs, dimensions and scalar parameters.
  • Aliasing and borrowed input requirements.
  • Results, mutations and numerical failures.
  • Sparse iterate storage and commitment.
  • Group steps and private storage.

solve!(x, f, g, AccProxGradDescent(), options=ProximalOptions())

Minimize the same least-squares lasso, elastic net or NormLinf problem as ProximalGradientDescent with accelerated proximal gradient descent, overwriting x, a dense Vector{T} with T = Float32 or Float64. The inputs, the options and their validation are those of ProximalGradientDescent, including a GroupNormL2 penalty with its group stopping check (see ProximalGradientDescent and ProximalOptions); in addition β and α must satisfy their bounds after conversion to T, and the dimensions must satisfy max(n, p) + 4 < 1/(4 eps(T)) and n p + 3 < 1/(4 eps(Float64)) (for Float32, max(n, p) < 2,097,148), which the rounding-error bounds of the line search need. Every refusal of an input, option or method setting happens before x is modified. A step error restores the last accepted x and rethrows, without a transaction guarantee for internal counters. The result shares x.

source
solve!(z, f, g, method::ADMMSolver, options=ProximalOptions(); u=nothing)

Minimize f(z) + g(z) and store the returned consensus iterate in z. Use f = SqrNormL2(λ, c) with a finite positive level and an unweighted g = NormL1(τ) with a finite nonnegative level. The levels must be exactly representable in the common Float32 or Float64 element type of z and c. The initial scaled dual is zero by default. Pass an independent, same-type buffer as u to start from its entries. Caller buffers are committed on normal return. Pass the returned iterate, scaled dual and penalty together to restart a solve. See ADMMResults and the ADMM input and result contract.

ProximalSolvers.ProximalOptions — Type
ProximalOptions(; maxiter=200, ftol=1e-6, xtol=1e-8, gradtol=1e-5,
  allow_f_increases=false, store_trace=false, show_trace=false,
  extended_trace=false, print_every=1, callback=nothing, time_limit=Inf,
  f_calls_limit=0, grad_calls_limit=0, prox_calls_limit=0, gaptol=0, gapevery=10)

Options for ProximalGradientDescent and AccProxGradDescent. Configure iteration limits, stopping tolerances, traces and callbacks. Any one of the iterate, objective or gradient tests can propose a stop; the applicable computed stationarity check must also pass. Defaults are suitable for an initial exploratory solve, without promising a particular coefficient accuracy.

using ProximalSolvers
options = ProximalOptions(maxiter=2000, ftol=1e-13, xtol=1e-11,
                         gradtol=1e-9, store_trace=true)

A successful stopping flag is not an exact optimality certificate; see the stopping rules.

ADMMSolver uses maxiter, prox_calls_limit and time_limit. It checks the limits before starting the next pair of proximal calls. See the ADMM options contract.

Keywords

  • maxiter=200: iteration limit.
  • ftol=1e-6: nonnegative objective-change tolerance; 0 disables that test.
  • xtol=1e-8: iterate-change tolerance.
  • gradtol=1e-5: gradient/proximal-residual tolerance; the final stationarity check has its own working-precision floor.
  • allow_f_increases=false: stop on a computed objective increase; true removes that exit without certifying the result.
  • store_trace=false: retain iteration states in the returned trace.
  • show_trace=false: print the iteration trace.
  • extended_trace=false: include copied iterates and gradients in trace metadata.
  • print_every=1: display and callback cadence.
  • callback=nothing: optional callback; receives the stored trace when tracing is enabled, otherwise the current state, and returning true requests a stop.
  • time_limit=Inf: elapsed-time limit in seconds.
  • f_calls_limit=0, grad_calls_limit=0, prox_calls_limit=0: limits on smooth-loss, gradient and proximal calls, respectively; zero means unlimited. Limits are checked after complete iterations, so a count can exceed its limit by the work of one iteration.
  • gaptol=0: reserved dual-gap stopping target; only 0 is accepted.
  • gapevery=10: reserved interval between dual-gap checks; it must be positive but has no effect. Neither gap-related argument is stored.

Extended help

For NormL1, ElasticNet and GroupNormL2, a proposed stop is checked against the applicable computed KKT residual; NormLinf uses a proximal-gradient mapping check. Neither certifies coefficient error. Check optimality independently when the accuracy matters. These options do not configure coordinate descent: CDSolver accepts unweighted NormL1(lambda), weighted NormL1(lambda, w), ElasticNet(lambda1, lambda2) and uncentered SqrNormL2(lambda) for dense or one-dimensional SparseIterate least-squares problems and stops by its change test.

For dense PGD with unweighted NormL1Nonneg(lambda) or IndNonnegative() (with lambda = 0), the KKT score is abs(grad[j] + T(lambda)) at a positive coefficient and max(-(grad[j] + T(lambda)), 0) at zero. The check uses the scale max(T(lambda), s * norm(X'y, Inf)) and tolerance floor 64eps(T); the complete threshold guards are in STOP-16. An infeasible starting point is refused before writes.

With ftol=0, an unchanged accepted iterate does not by itself count as convergence. Float32 PGD can instead report stagnated=true and converged=false under the documented stagnation condition. An objective increase, an iteration/call limit and convergence are separate conditions; inspect the individual result flags rather than inferring one from another.

The display label |g(x)| denotes an internal stopping residual, not the value of the supplied penalty. Data and iterate buffers keep their working type; Float64 tolerances or diagnostics do not increase Float32 coefficient accuracy.

  • Iteration order, traces, callbacks and limits.

ProximalSolvers.CDResults — Type
CDResults

Result sharing the caller's vector or SparseIterate as minimizer, with minimum, passes, converged, maxchange and tolerance. The compatibility field kkt_checks = 0 is a sentinel. gap is NaN except after a certified square-root lasso run (see CDSolver), where converged = true and gap is the certified upper bound on (P - P*)/P*. For the square-root lasso, passes includes the passes of the fallback after an uncertified stop, and is at most maxpasses. For the least-squares lasso, elastic net, ridge and group lasso, converged reports the change test and gap is NaN.

source
ProximalSolvers.ADMMResults — Type
ADMMResults

The result of solve! with an ADMMSolver. minimizer aliases the caller's vector and minimum is the objective there. iterations counts completed iterations, with two proximal calls each in prox_calls.

r_norm, s_norm, eps_pri and eps_dual describe the final residual tests. They are NaN if no iteration ran. u is the final scaled dual variable and ρ is the penalty used for the final tests, or the starting penalty if no iteration ran. An explicit dual buffer passed to solve! also aliases the result. status records the exit and converged is true for :converged. See the ADMM contract.

ProximalSolvers.OptimizationResults — Type
OptimizationResults

Result from plain or accelerated proximal gradient descent. minimizer aliases the caller's coefficient vector; minimum is the reported objective there. iterations counts steps. converged means that a stopping proposal passed the applicable computed stationarity check. Copy minimizer before reusing the coefficient array for another solve.

iteration_converged reports reaching the iteration limit, not successful optimization; see result semantics.

Extended help

Fields to inspect

  • method, minimizer, minimum: solver, shared coefficients and objective.
  • iterations, iteration_converged: work completed and whether maxiter was reached.
  • converged, x_converged, f_converged, grad_converged: the final stopping flags after the stationarity check; the last three are all false when it fails.
  • x_tol, f_tol, g_tol, x_residual, f_residual, g_residual: thresholds and reported diagnostics, defined precisely by the stopping contract.
  • f_increased: whether the last computed objective exceeded its predecessor; this can coexist with convergence. The result does not store allow_f_increases.
  • trace: stored iteration states when requested.
  • f_calls, grad_calls, prox_calls, backtrack_steps: oracle and line-search counts. PGD and APG do not count every kind of trial identically.
  • call_limit_reached: a call limit was reached.
  • stagnated: the documented Float32 PGD stagnation exit; this is not a convergence or accuracy certificate, and other exit flags can also be true.
  • gap: NaN, because this result type does not compute a certified duality gap.

For NormL1, ElasticNet and GroupNormL2, the stop check uses the applicable computed KKT residual; NormLinf uses the generic proximal-gradient check. A small residual does not bound coefficient error on an ill-conditioned design. With ftol=0, f_converged is false and the objective residual is reported only.

See the exact stopping definitions and results and failure rules.

ProximalSolvers.LineSearches.BackTracking — Type
BackTracking(; α = 0.9, β = 0.5, Lexact = Inf)

Backtracking settings for ProximalGradientDescent. The step size is 1/L; each iteration initially replaces L by α*L, and rejected trials raise it using the local curvature estimate and β. The object stores settings only and can be shared between solves; iteration bookkeeping belongs to the solver state.

using ProximalSolvers
ls = ProximalSolvers.LineSearches.BackTracking(α=0.9, β=0.5)
method = ProximalGradientDescent(ls=ls)

Step acceptance does not certify the returned optimum; see the line-search contract.

Extended help

The reference algorithm is TFOCS's private/tfocs_backtrack.m.

  • α=0.9: curvature reduction before an iteration; requires 0 < α <= 1.
  • β=0.5: raises curvature after a rejection, shrinking the step; requires 0 < β < 1.
  • Lexact=Inf: positive cap used by the curvature-estimate retry update.

The search starts with function-value estimates and can switch to gradient estimates when values are too close to compare. The least-squares implementation can recheck a rejected trial using its computed curvature. A trial with a nonfinite image or value is not accepted. Certain overflowing step norms are rescaled, but the implementation does not recover every underflow, cancellation or nonfinite intermediate.

These checks do not supply a general rounding certificate. A line-search error is propagated by solve! after restoring the last accepted coefficient vector. The precise update formulas, recheck exceptions and range limitations are in LS-01.
