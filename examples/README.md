# Examples

The scripts here are documentation pages and tests at the same time. The documentation
build turns each registered script into a page (see `docs/make.jl`), and `test/examples.jl`
runs every `.jl` script under this folder, subfolders included. The checks of a script are
`@assert` statements, so a failed check stops the script with an error.

## Reproduce the figures

The documentation [Examples Gallery](https://mlakolar.github.io/ProximalSolvers.jl/dev/examples/)
links to each tutorial and shows the figure generated by its script. Build the documentation to
recreate the figures and pages locally. This requires Julia 1.11 or later, because `docs/Project.toml`
uses `[sources]`. This requirement concerns the documentation environment; the package remains
compatible with Julia 1.10.8, and standalone examples run with the package environment.

```sh
julia --project=docs -e 'using Pkg; Pkg.develop(path=pwd()); Pkg.instantiate()'
julia --project=docs docs/make.jl
```

Open `docs/build/examples/index.html`. Each thumbnail is generated as
`docs/build/examples/<folder>/<script-name>.svg`. The plotting cells use Plots from
`docs/Project.toml`. Their Literate markers leave standalone execution and the ordinary
examples tests independent of the plotting environment.

When adding an example, save its primary figure as `<script-name>.svg` in a
documentation-only plotting cell, embed it near the tutorial introduction, and register
the gallery category and description along with the script path in `docs/make.jl`.

## How the folder is organized

- `problems/` holds one canonical tutorial per optimization problem, named after the
  problem (`lasso.jl`, `elastic_net.jl`, ...). A tutorial can solve its problem with several
  solvers, in separate sections.
- `comparisons/` holds comparisons of solvers on a problem, named `<problem>_solvers.jl`.
- Some tutorials in `problems/` are statistical applications of a supported problem rather than new problems. The documentation lists them under "Statistical applications", and they add no row to the matrix of [Supported problems](../docs/src/support.md). The sparse logistic-regression tutorial is listed under "Problems" as the tutorial of the matrix row for `LogisticLoss`.
- A solver is not a problem. A weighted lasso, for example, is `LeastSquaresLoss` with a
  weighted `NormL1(λ, w)`. `CDSolver`, `ProximalGradientDescent` and `AccProxGradDescent`
  support it (see [Supported problems](../docs/src/support.md)), and it is documented in
  `problems/weighted_lasso.jl`, not as a separate solver.

A new script is registered in `docs/make.jl`, which stops with an error when a `.jl` script
under this folder is not registered or a registered script is missing. A change that adds or removes support for a combination of
problem, solver, iterate and element type also changes the matrix of
[Supported problems](../docs/src/support.md).

The elastic-net script also demonstrates uncentered `SqrNormL2` ridge with
`CDSolver`. It checks the coefficient owner and agreement within `1e-7` in the
infinity norm with the direct ridge normal-equation solution.

Both solver comparisons measure the time to reach the same independently checked objective
gap and KKT violation. The scripts print tables, and the documentation build adds figures. The
lasso comparison draws its ADMM solves as unconnected markers, one marker shape for each `ρ`,
because no single history joins solves with different `ρ`. Its ADMM times exclude the one-time
SVD setup of the loss, which the page reports and adds in a separate row; this is the tradeoff
of the cached SVD that the prose of the page explains. The lasso page and the comparison keep
their published paths, anchors and gallery cards; no gallery page is added.
The lasso comparison also has a downloadable notebook that uses Plots. Times are illustrative,
from one machine and one run. See [Benchmarks and performance](../docs/src/benchmarks.md)
for the repository's benchmark evidence.
