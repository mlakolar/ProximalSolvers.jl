Results and troubleshooting

The solver writes into the array or coordinate owner that you supply. The returned result reports the final point, objective and stopping information.

Read the result

using ProximalBase, ProximalSolvers

X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
f = (1 / length(y)) * LeastSquaresLoss(y, X)
g = NormL1(0.1)
x = zeros(2)

r = solve!(x, f, g, CDSolver())
@show r.minimum                  # value of f(x) + g(x)
@show r.passes                   # CD passes performed
@show r.converged                # historical change stopping
@assert r.minimizer === x        # not a separate coefficient copy
saved_coefficients = copy(x)

Both result families provide minimizer, minimum and converged, but the iteration details differ.

A true converged flag is not a KKT certificate and does not by itself certify statistical or optimization accuracy. Check the objective and, where necessary, the optimality conditions independently. On this small example the analytic coefficients are [1.7, -0.925]; do not use that reference for your own data.

Avoid accidental overwrites

solve! modifies x in place. In particular:

first_solution = copy(x)
another_result = solve!(x, f, NormL1(0.2), CDSolver())
# first_solution is preserved; r.minimizer refers to the now-reused x

If x is a SparseIterate, the final state is committed to the same owner only after a finite completed CD run. Its active coordinates may be compacted or reordered; do not hold old activevalues or activecoordinates views across solves. A numerical exception leaves the caller's owner unchanged, but the RNG used by random-order CD may have advanced. PGD instead restores the last accepted dense point after a numerical step exception.

Where to look next

The Getting started guide explains the objective and the first run. Choosing a solver describes configuration, Supported API and migration records the full current limitations, and Numerical behavior documents stopping and exceptional arithmetic. The API reference contains individual Julia docstrings.

If you are looking for sparse design matrices, generalized losses, group penalties, path algorithms or the historical larger solver suite, these are not features of the current development master. They remain separate restoration work; the historical code is preserved under legacy/full.
