API reference

This is the complete callable reference, including some historical constructor keywords that intentionally reject unsupported features. For practical options, see Choosing a solver; for deferred keyword combinations, see Supported problems.

ProximalGradientDescent() provides its supported backtracking line search by default. The qualified type ProximalSolvers.LineSearches.BackTracking appears below for API completeness. Ordinary users do not need to import or instantiate it separately.

ProximalSolvers.ProximalSolver — Type
ProximalSolver

Abstract supertype of CDSolver and ProximalGradientDescent, passed to solve!.

ProximalSolvers.CDSolver — Type
CDSolver(; maxpasses=100_000, tol=1e-7, order=:random, relative=true,
           momentum=nothing, rng=Random.default_rng(), anderson=0,
           gaptol=0, gapsafe=false)

Coordinate descent for the least-squares lasso. Call solve!(beta, f, g, CDSolver()) with matching Float32 or Float64 design/response data and coefficients. The coefficient storage can be a dense Vector or a one-dimensional ProximalBase SparseIterate.

CDSolver() uses random coordinate order and the algorithm's default momentum behavior, a reasonable exploratory choice. For deterministic tutorial examples use CDSolver(order=:cyclic, momentum=false); for repeatable random order supply rng=Xoshiro(seed) from Random. The borrowed RNG advances when used. Cyclic order does not support momentum=true.

tol (default 1e-7) measures coefficient change, not independent optimality. With relative=true, the stopping threshold depends on the response scale. relative=false makes it an absolute change threshold; maxpasses limits the run. An end-of-pass convergence flag does not guarantee a small KKT residual. For reported fits, check optimality independently. Anderson acceleration, gap certificates and screening are not implemented and are rejected.

A SparseIterate is solved on a private copy retaining its initial active zeros and coordinate order. After a completed finite run the caller receives the complete final state, including any zero-coordinate compaction. The copy needs O(p) extra storage. See solve! and the solver guide.

ProximalSolvers.ProximalGradientDescent — Type
ProximalGradientDescent(; ls=LineSearches.BackTracking(), normalized=false,
                         debias=0, preconditioner=:none)

Proximal gradient descent (PGD) for least-squares lasso with a dense Vector{Float32} or Vector{Float64} coefficient iterate. Each iteration takes a gradient step for the smooth least-squares loss and applies the NormL1 proximal operator (soft thresholding); backtracking adjusts the step size.

ProximalGradientDescent() uses the supported LineSearches.BackTracking() line search. The options normalized=true, debias>0, preconditioner!=:none and custom line searches are not implemented and are rejected. These constructor keywords remain for compatibility with earlier versions.

Pass ProximalOptions(...) as the fifth argument to solve! to configure stopping tolerances and iteration limits. The defaults may stop after only 3–4 correct digits on the small tutorial examples. converged=true means a stopping rule was satisfied, not that the result is an accurate minimizer. Tighten tolerances and check KKT conditions independently before reporting numerical results. See the solver guide and numerical behavior.

ProximalSolvers.solve! — Function
solve!(x, f, g, CDSolver())
solve!(x, f, g, ProximalGradientDescent(), options=ProximalOptions())

Minimize a least-squares lasso, overwriting x. x is a dense Vector{T}, T=Float32 or Float64; CDSolver also accepts a one-dimensional SparseIterate{T} (see below), while ProximalGradientDescent refuses it. The loss uses same-type Matrix X and Vector y, and the penalty is an unweighted finite nonnegative NormL1. Use (one(T)/T(n))*LeastSquaresLoss for normalized lasso; raw LS keeps its unnormalized meaning. One positive finite scalar LS wrapper is supported. Borrowed X/y must not alias mutable x or change during a solve. Results share x; copy it to retain earlier coefficients. Unsupported inputs/options fail before mutation. Convergence uses historical stopping tests, not a KKT certificate. Finite intermediate arithmetic is required. PGD step errors restore its last accepted x and rethrow, without a transaction guarantee for internal counters.

CD on a dense vector. A numerical error, including a nonfinite final objective, leaves x unchanged.

CD on a SparseIterate. All checks of inputs, options, shapes, finiteness of the active values, representable parameters and detectable aliases of x with X or y (through its backing storage, whether or not it has active entries) happen before the iterate is copied and before the RNG is used, so a refused call neither changes x nor advances the RNG. The solve then runs on work = copy(x), which keeps the values, active zeros and the order of the active coordinates, with the same passes, activation, per-pass removal of zero coordinates, momentum and stopping as for a dense vector. It needs O(p) extra storage, and nothing is reconstructed through a dense vector.

When the run completes, with a finite objective, x receives the whole final state of work by a same-shape copyto!(x, work): this includes a finite maxpasses outcome with converged = false and its warning, and maxpasses = 0, which leaves exactly the entry state, including active zeros and slot order. Zeros that a pass removed from work are not restored, and the order is not sorted. The result's minimizer is x itself. A numerical error (such as a nonfinite step or objective) throws with the values, the active set, signed zeros and the order of x unchanged; the borrowed RNG may already have advanced. After a successful call, take activevalues(x) and activecoordinates(x) again: handles taken earlier may no longer describe the active set.

ProximalSolvers.ProximalOptions — Type
ProximalOptions(; maxiter=200, ftol=1e-6, xtol=1e-8, gradtol=1e-5,
  allow_f_increases=false, store_trace=false, show_trace=false,
  extended_trace=false, print_every=1, callback=nothing, time_limit=Inf,
  f_calls_limit=0, grad_calls_limit=0, prox_calls_limit=0, gaptol=0, gapevery=10)

Options for proximal gradient descent (PGD). The defaults prioritize an exploratory solve rather than a guaranteed number of accurate digits. PGD stops when any of the iterate-change (xtol), objective-change (ftol), or gradient/proximal-residual (gradtol) criteria succeeds. converged=true is therefore not a KKT certificate.

maxiter caps iterations; store_trace, show_trace and extended_trace control reporting. print_every sets display/callback cadence; a callback receives the trace when it is stored, otherwise the current state. The result display labels an internal gradient/proximal residual as |g(x)|: it is not the value of the supplied penalty.

Call/time limits are checked after complete iterations, so counts can exceed limits by one iteration. A zero call limit means unlimited. Float32/Float64 iterate buffers retain native arithmetic; some scalar tolerances and diagnostics are held in Float64, without increasing coefficient accuracy. Positive gaptol is not supported; positive gapevery has no effect when gaptol=0.

ProximalSolvers.CDResults — Type
CDResults

Result sharing the caller's vector or SparseIterate as minimizer, with minimum, passes, converged, maxchange and tolerance. Compatibility fields kkt_checks=0 and gap=NaN are sentinels, never computed certificates.

ProximalSolvers.OptimizationState — Type
OptimizationState{T<:ProximalSolver}

One iteration of a trace: iteration, the objective fg_x = f(x) + g(x), the relative change dxx = ‖x - x'‖ / ‖x‖, the inverse step size L, and a metadata dictionary that holds the iterate and gradient when extended_trace = true.

ProximalSolvers.OptimizationTrace — Type
OptimizationTrace{T}

A Vector{OptimizationState{T}}, stored in the results when store_trace = true (see ProximalOptions).

source
ProximalSolvers.OptimizationResults — Type
OptimizationResults

Result from proximal gradient descent. minimizer aliases the caller's coefficient vector; minimum is the reported objective at that iterate. iterations counts steps and converged means at least one stopping criterion succeeded, not necessarily that the solution satisfies KKT optimality. iteration_converged reports reaching the iteration limit, not successful convergence.

The result also stores stopping flags, residuals and tolerances, optional trace, call counts and backtracking counts. backtrack_steps includes accepted nonzero line-search trials. gap=NaN means a dual gap was not calculated, not that the gap is zero.

ProximalSolvers.LineSearches.BackTracking — Type
BackTracking(; α = 0.9, β = 0.5, Lexact = Inf)

The backtracking line search of TFOCS (private/tfocs_backtrack.m). Each iteration starts from L ← α L, where 1/L is the step size, and while the local Lipschitz estimate L̂ of the step exceeds L it retries with L ← min(Lexact, max(L̂, L / β)). L̂ comes from function values until they are too close to compare in floating point, and from gradients after that. An LS trial whose image or value overflows is never accepted: it gives no estimate, and the search retries with L ← L / β.

The object holds settings only and can be shared between solves; the bookkeeping lives in the solver state.
