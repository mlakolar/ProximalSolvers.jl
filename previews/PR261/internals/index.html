Developer architecture

This page is for contributors working on the implementation, not a prerequisite for using the package. Begin with Getting started and Supported problems if you are new.

High-level organization

The development core intentionally keeps only two separate least-squares lasso engines:

  • Coordinate descent: builds and updates a ProximalBase SparseIterate internally, visiting full coordinate sets and then active ones. Dense vectors are copied into the internal representation; caller-supplied sparse coefficient storage is copied privately and committed on a finite completed run.
  • Proximal gradient descent: maintains full dense iterate and gradient buffers, using a least-squares image cache and backtracking line search.

Losses, L1 proximal operations and sparse coefficient storage live in ProximalBase. Solver orchestration and algorithm-specific results live here. The two solvers intentionally retain separate option and result types rather than introducing an untested shared engine.

For exact source-level contracts, exceptional recovery, branch history, validation policy and deferred APIs, consult Contributor implementation notes. For a beginner explanation of the algorithms, see What problem, which algorithm?.
