Limits of the stopping tests

This page keeps its published links. The full material is now organized in Learn and Contracts.

See the current section.

Select stopping conditions in dense least-squares PGD

Use stopping to choose a condition and limits=MaxIterations(n) to cap the number of accepted updates. These keywords also apply to AccProxGradDescent on the supported dense least-squares route. AnyOf accepts the first passing condition. AllOf needs its conditions to pass at the same checkpoint. IterateChange and ObjectiveChange measure progress between accepted points. UserStop accepts a predicate over scalar checkpoint metadata. With NormL1 or ElasticNet, ScaledKKT(rtol=...) checks computed coordinatewise stationarity. The stopping contract specifies the comparison scales, option conflicts and checks available at the cap.

using ProximalBase, ProximalSolvers

X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
x = zeros(2)
rule = AllOf(IterateChange(atol=1e-10, rtol=1e-7),
             ScaledKKT(rtol=1e-5))
r = solve!(x, LeastSquaresLoss(y, X), NormL1(0.1),
           ProximalGradientDescent(); stopping=rule, limits=MaxIterations(200))
termination(r)

termination(r).satisfied says whether the selected expression passed. r.converged is true when the winning branch includes a passing ScaledKKT. The result contract describes the stop reason, winning leaves, observations and counts. Omit both keywords to use the solver’s default stopping policy.

At the iteration cap, a tie can use stored objective values. ScaledKKT, IterateChange and UserStop are marked :not_checked there. A solve using ScaledKKT alone reports reason = :limit and converged = false if it reaches the cap. In APG, an evaluated KKT check uses the gradient at the accepted point and includes its cost in the oracle counts.

Select stopping conditions in scalar coordinate descent

For dense vector least-squares lasso with unweighted NormL1, turn momentum off and pass a rule, a pass budget, or both. A full sweep visits all coefficients. An active sweep revisits the active coordinates. Both count toward MaxPasses. ObjectiveChange compares consecutive full sweeps. UserStop can run after either kind of sweep before the cap.

using ProximalBase, ProximalSolvers

X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
x = zeros(2)
r = solve!(x, LeastSquaresLoss(y, X), NormL1(0.5),
           CDSolver(order=:cyclic, momentum=false);
           stopping=ObjectiveChange(), limits=MaxPasses(20))
@assert x == [1.5, -0.875]
@assert termination(r).satisfied
@assert termination(r).counts.full_passes == 2
termination(r)
(reason = :rule, satisfied = true, winning_branch = ((),), iteration = 3, limit = MaxPasses(20), limit_reached = false, observations = ((path = (), name = :ObjectiveChange, evidence = :progress, status = :pass, value = true, threshold = true, scale = missing),), counts = (full_passes = 2, active_passes = 1, coordinate_visits = 6, objective_evaluations = 2))

The orthogonal columns give the lasso solution [1.5, -0.875] on the first full sweep. The next full sweep has the same objective and satisfies the rule. Read termination(r).satisfied for progress and termination(r).counts for full passes, active passes, visits, and objective evaluations. Check full-point stationarity when accuracy matters. CD-10 specifies the checkpoints and their cost.

The criterion and a certificate

See the current section. For PGD and APG on least squares with a dense vector response and NormL1 or ElasticNet, a kept stop records that each coordinate's computed score passed the rule: below its computed threshold, or at most 0 at an exact zero scale, where no threshold is formed. In exact arithmetic the same comparison would bound the decrease available from each coordinate of the model that the check scores, under the conditions of STOP-21 (that model is the objective of the solve when their coefficients agree); neither bounds the error of the objective or the coefficients in general, and an exact or near-exact fit can return converged = false. The matrix-response lasso of IN-10 keeps the λmax-based check of STOP-03. For square-root lasso, a bounded fallback can certify an uncertified stopped point or return a point with a proved lower objective; recovery at exact fits is not guaranteed. See the bounded recovery rule.
