Supported problems

This page describes the current GitHub development master branch, not the wider feature set in historical releases.

What works today?

The supported objective is a lasso:

\[\min_\beta\quad \frac{s}{2}\|y-X\beta\|_2^2+\lambda\|\beta\|_1,\]

where s=1 for raw LeastSquaresLoss or s=1/n for the usual normalized convention.

InputSupported
Design matrix XNonempty, finite, dense Matrix{Float32} or Matrix{Float64}
Response yFinite vector with the same element type and length(y) == size(X,1)
Coefficients betaSame-type dense vector for CD or PGD; alternatively, one-dimensional ProximalBase SparseIterate for CD only
LossLeastSquaresLoss or one finite positive scalar multiple of it
PenaltyUnweighted NormL1(lambda) with nonnegative finite lambda
SolversCDSolver, ProximalGradientDescent

The three numerical arrays use one common T (Float32 or Float64); mixed-element-type X, y and coefficient arrays are not supported. The finite loss scale and penalty level must be representable in T without overflow or rounding a nonzero scalar to zero. They may be supplied in a different scalar type, including a representable Float64 literal in a Float32 problem; this narrow convenience does not imply mixed-precision array support or a guarantee about every intermediate arithmetic type.

The data must not be modified while a solve is running. The coefficient vector (or the supported CD SparseIterate) is mutated in place, so do not alias it to X or y. To retain a result, save copy(beta). See Numerical behavior for numerical recovery limits, solver stopping and diagnostics.

For an executable complete example, see Getting started. For using sparse coefficients, see the sparsity tutorial. The design matrix still must be dense, even when the coefficients use SparseIterate.

What is not supported yet?

The current development core intentionally excludes the following:

FeatureCurrent status
Sparse design matrices; sparse or view-based dense coefficientsDeferred
Generalized losses, matrix responses, intercepts/offsetsDeferred
Weighted or group penalties, generalized penalty combinationsDeferred
Penalty paths, screening and dual-gap certificatesDeferred
ADMM, Newton, accelerated gradient, primal-dual, SLOPE, graphical modelsDeferred
Generic workspaces, refitting, reweightingDeferred
PGD with SparseIterate coefficientsDeferred
CD anderson>0, gaptol>0, gapsafe=trueRejected; not implemented
PGD normalized=true, debias>0, preconditioner != :noneRejected; not implemented

Some rejected keywords remain accepted by constructors only to provide informative errors and compatibility with historical signatures. Do not interpret their presence as available functionality. The reported gap=NaN and CD's kkt_checks=0 are placeholders, not computed certificates.

About previous versions

The registered package and historical legacy/full branch may expose features that this development branch intentionally does not. These are different development stages; this documentation does not provide a migration procedure for every historical algorithm. Consult Getting started for source installation.

See Numerical behavior for stopping and precision. Detailed implementation, failure transaction and internal algorithm contracts are preserved under Contributor implementation notes.
