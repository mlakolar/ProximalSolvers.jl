Ball rounding admission: measurements

This page records the measurements behind the admission of an IndBallL2 trial whose ProximalBase value is Inf (IN-08, issue #537). They are observations at stated revisions, not solver guarantees; the rule and its error bounds are in the clause.

evidence-ball-rounding Reproduction at the base

Statement. Measured at ProximalSolvers master 202545cc with ProximalBase bc9e888d, on a cluster (Slurm), Julia 1.13.3. The probe drew 20,000 random four-entry IndBallL2 projections per regime and counted those whose fused value_and_prox! value is Inf. The last column is the largest true relative violation (‖x‖ - r) / r among the Inf outputs, computed in BigFloat.

  • Solves. The IndBox and IndBallLinf controls (PGD and APG) and the IndNonnegative control (PGD) passed in both precisions, and so did the active and interior IndBallL2 controls. A sweep of 200 random ordinary active-ball problems (scales 1e-3 to 1e3) failed 0 of 200 for each of the four combinations of method and precision. In Float64, IndBallL2(1e-150) failed with PGD and with APG, and IndBallL2(1e157) failed with PGD, all with "the gradient step did not produce a finite objective". The Float32 boundary cases passed in that draw.
  • Attribution. The failure is not in the curvature test. PGD's backtrack! reads the smooth value, not the penalty value. APG's search requires the smooth value of a trial to be finite, and for a nonfinite smooth trial value it attempts a curvature increase, which can error if next_curvature cannot increase; its certified image inequality reads the displacement and the images. The Inf comes from ProximalBase's fused value of the stored projection, through state.g_x. The outer guard isfinite(state.f_x + state.g_x) in _solve_gradient! sees the trial that the step returns and rolls back when the composite is not finite. In APG with momentum the restart test f_x + g_x > f_x_previous + g_x_previous fires on such a trial first. The retry without momentum from x_previous can be accepted and the solve continues, which is why some solves passed; the next outer iteration, if one runs, extrapolates with momentum 1/4. The retry can also fail inside the search, for example when next_curvature cannot increase, or return a trial that reaches the guard. In the first step, and in the retry without momentum within a restarting iteration, a trial skips the momentum comparison and reaches the guard if the search returns it.
  • Ordinary range. No failing case of the supported four-entry scope appeared in the ordinary range. The admission applies to a trial whose ProximalBase value is Inf, which the ordinary-range solves did not produce.

evidence-ball-rounding-cases Trial points and the base

Statement. The tests of IN-08 use hard-coded targets. A search over one-iteration solves found them: each is a start x0 = 0 whose first trial of both PGD and APG ends on a stored projection with value Inf. For the radii 1e-150 (Float64) and 1e-16 (Float32), with X = 2I and loss scale 1/4, the first trial projects the target itself and the stored violation was below 0.4 eps(T). The huge-scale cases use the design 1e-150 I (Float64) or 1e-17 I (Float32) and radii near one tenth of the norm of the target. The retained Float32 cases were found at draws 478 and 485 of one search (cumulative counts), because ProximalBase's Inf is rare there.

At the base, test/constrained_least_squares.jl with the new testsets, run against a module built from the base source, passed 2098 assertions and had 14 errors: each of the twelve end-to-end admission testsets (three testsets, two precisions, two methods) raised "the gradient step did not produce a finite objective", and the two helper testsets raised because the helper does not exist at the base. The testset "Reported minimum: smooth term and penalty term" passed at the base, because the behavior it checks is not changed by the admission. The existing testset "Exceptional Euclidean projection rolls back" passed unchanged.

evidence-ball-rounding-rounding Rounding observations

Statement. Julia 1.10.12 and 1.13.3 gave the same results, on a cluster (Slurm), at ProximalBase bc9e888d. They are observations that accompany the comment of _within_ball_tolerance, not guarantees.

  • Least positive radius. For r = nextfloat(zero(T)) and the trial (a, a, 0, -0.0), ProximalBase stores (r, r, 0, -0.0) for a = 1, (-r, -r, 0, -0.0) for a = -1, with fused value Inf and a relative violation of sqrt(2) - 1, in Float32 and Float64. For a = 0 it stores zeros with value 0. The check rejects the first two (the rollback test uses a = 1).
  • A small square lost at a rounding tie. For Float64, x = [1.0, 2.0^-26, 2.0^-53, 2.0^-600] and r = 1 - 8eps(Float64), the helper admits. The scaled square of the last entry rounds to zero. In 1600-bit arithmetic the norm without that square is exactly the midpoint between 1.0 and nextfloat(1.0), and the norm with it is above the midpoint, so the correctly rounded norm changes from 1.0 to nextfloat(1.0), while the computed threshold is 1.0.
  • A subnormal scaled entry rounded up. With largest magnitude 2.0 and another entry prevfloat(2floatmin(Float64)), the scaled entry is floatmin(Float64).
  • A computed cutoff. At r = 1.1 (Float64), the point (t, 0, 0, 0) with t the rounded threshold r (1 + 8eps) is admitted at a true violation of 8.18 eps.
  • An exterior point with value zero. The point (1, sqrt(eps(T))/4, 0, -0.0) at radius one has g(x) == 0 in Float32 and Float64, with true violations of 3.7e-9 and 6.9e-18. The point passes the indicator's feasibility check, and a PGD solve with X = 2I

accepted it as a start.

evidence-ball-rounding-kernels Reuse of ProximalBase kernels

Statement. The Float64 check scales the entries and the radius by two normal powers of two built with ProximalBase's _normal_power and applied with _scale_value, and both precisions sum the four squares with ProximalBase's _ball_l2_sum4. A differential test compared the final implementation, a variant that uses _power_factors (the single factor 2^-1023 at k = -1023, as at 4a6df100) and a variant that sums with _square_scaled_sum (a compensated sum) against the implementation of a490f020, which used a local split into 2^k1 and 2^(k - k1) and a plain loop sum. It ran on Julia 1.10.12 and 1.13.3, at ProximalBase bc9e888d, under gradual underflow and under set_zero_subnormals(true).

The generated cases are four-entry Float64 points with signs and zeros, in four groups of 100,000 points each (maximum in [2^1023, floatmax] with other entries down to the subnormal range; subnormal-scale maxima, which can include floatmin(Float64), a normal number; maximum near 2^-1022 and 2^1022; ordinary scales). For each point the radii are the threshold radius, centred at the BigFloat norm divided by 1 + 8eps and rounded to Float64, its 6 neighbours on each side and 3 random radii around it, when that centre is finite and positive; unusable random radii are omitted. The constructed cases are 549: the tie example, scaled by powers of two, with its neighbouring radii; axis points at the rounded threshold with signs and zeros; and largest entries at and above 2^1023 with radii around 2^1022, including r = 1.

For x = [2^1023, nextfloat(2^-52), 0, -0] and r = 2^1022, a490f020 and the final implementation reject in both modes, and the _power_factors variant admits under flushing, where its subnormal factor 2^-1023 becomes zero. Under gradual underflow the factors of _power_factors have product exactly 2^k for every k from -1074 to 1074, and ldexp(1.0, -1023) is the subnormal 2^-1023 on both versions.

The compensated sum changes decisions near the cutoff, with no exact tie needed. For Float64 x = [1.0, 2^-26, 1.25 * 2^-27, 1.25 * 2^-27] and r = 1 - 8eps, a490f020 and the final implementation admit and the compensated variant rejects. The Float32 counterpart x = [1 + 2^-20, 2^-26, 1.25 * 2^-27, 1.25 * 2^-27], r = 1 behaves the same way. The tie example above gives the same decision in all three variants. Under gradual underflow, over 1,300,000 generated Float32 decisions, the final implementation agreed with the plain Float64 loop and the compensated kernel also gave no difference, so the generated Float32 points did not reach such a case. _ball_l2_sum4 and the loop s = 0.0; s += abs2(...) gave bitwise equal sums on 2,000,000 random four-entry vectors, also under gradual underflow.

evidence-ball-rounding-minimum Smooth term of the reported minimum

Statement. The earlier IndBallL2 returns with minimum = Inf in this change were measured at c0878e5b and 1d4ac095, under the earlier policy of this pull request, in which the result re-evaluated the standalone g(x) at the returned point for the penalty term of minimum. The base 202545cc and the IndBox control reported the cached penalty, as the current policy does; the comparison below with them is a separate observation. From 44bd7d88 minimum is the monitored objective, the cached smooth value plus the monitored penalty (IN-08). Admission gives the monitored penalty zero, so the objective is finite for an admitted point that passes the outer finiteness check and is returned. The smooth term of minimum is the cached smooth value of the accepted trial, as for the other penalties of these solvers, and it can differ from the standalone loss at the returned point by rounding. A Float32 case shows it: y = vcat(fill(ldexp(1f0, 63), 2), fill(ldexp(1f0, 51), 4)), the loss 2f0 * LeastSquaresLoss(y, zeros(Float32, 6, 4)), x = zeros(Float32, 4) and one iteration (ProximalOptions(maxiter=2, prox_calls_limit=1)). With IndBallL2(1f0) and with IndBox(-1f0, 1f0), with PGD and with APG, at 202545cc and at c0878e5b, on Julia 1.10.12 and 1.13.3 (16 runs), each returned x = 0 and minimum = 1.701412e38, while the standalone f(x) + g(x) was 1.7014118e38, one unit in the last place lower. The base returned the same minimum for IndBox, so the difference is not introduced by the admission.

evidence-ball-rounding-perf Paired performance

Statement. The base source 202545cc, the implementation f2465717 and a second copy of its source (the A/A control) were loaded in one process on a cluster (Slurm) node, Julia 1.10.12 and 1.13.3, with one Julia thread. The BLAS thread count was 32 on Julia 1.10.12 and 2 on Julia 1.13.3; all three sides ran in one process, so each pair shares the count. For each case the three sides solved the same problem in alternating order inside each repetition (the order rotates), 30 repetitions in each of 5 rounds. The ball problems have four coefficients and 40 observations, and each timed call repeats the solve 50 times. The other problems have 200 observations and 50 coefficients, with the loss scaled by 1/n: IndBox(-0.5, 0.5) (active), IndNonnegative (PGD only), NormL1 and ElasticNet. The ratios are medians of the per-repetition paired ratios.

Over the 36 combinations of case, method, precision and Julia version, the median head/base ratio lies between 0.985 and 1.022, and the median copy/head ratio of the control between 0.967 and 1.021. The allocation of one solve is equal on the three sides in all 18 cases for each Julia version. In all of them the minimizer bits, iterations, minimum and converged of the head equal the base's, and those of the copy equal the head's.
