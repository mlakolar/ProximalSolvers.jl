API reference

This is the complete callable reference, including some historical constructor keywords that intentionally reject unsupported features. For practical options, see Choosing a solver; for deferred keyword combinations, see Supported problems.

ProximalGradientDescent() provides its supported backtracking line search by default. The qualified type ProximalSolvers.LineSearches.BackTracking appears below for API completeness. Ordinary users do not need to import or instantiate it separately.

ProximalSolvers.CDSolver — Type
CDSolver(; maxpasses=100_000, tol=1e-7, order=:random, relative=true,
           momentum=nothing, rng=Random.default_rng(), anderson=0,
           gaptol=0, gapsafe=false)

Coordinate descent for dense Float32/Float64 least-squares lasso (including weights), elastic net, ridge, nonnegative least squares and nonnegative lasso (on a dense vector), group lasso and square-root lasso. Use a dense vector or one-dimensional SparseIterate for scalar problems, a BlockIterate for groups, or matrix coefficients for row-group multi-response regression. The nonnegative problems are for a dense vector only. solve! updates the supplied coefficients. For deterministic scalar examples, choose order=:cyclic, momentum=false.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                CDSolver(order=:cyclic, momentum=false))

converged is a change test, with an additional certificate for square-root lasso; see result semantics.

Keywords

  • maxpasses=100_000: maximum number of coordinate passes.
  • tol=1e-7: change tolerance; it is not an independent accuracy target.
  • order=:random: random coordinate order; :cyclic is deterministic.
  • relative=true: scale the change test using the response and coordinate curvature; false uses an absolute change threshold.
  • momentum=nothing: use the algorithm's default momentum policy. false disables momentum. true is unsupported for cyclic order and group problems.
  • rng=Random.default_rng(): borrowed random generator, advanced when used. Create a fresh seeded generator to reproduce a random order.
  • anderson=0: reserved Anderson-acceleration setting; only 0 is accepted.
  • gaptol=0: reserved dual-gap stopping target; only 0 is accepted.
  • gapsafe=false: reserved gap-safe screening switch; only false is accepted. These three compatibility settings are not stored or used.

Extended help

The data arrays share one Float32 or Float64 element type. With least squares, use NormL1(lambda), NormL1(lambda, w), ElasticNet(lambda1, lambda2), ElasticNet(lambda1, lambda2, w) or an uncentered SqrNormL2(lambda) for scalar coefficients. Ridge via SqrNormL2 is supported only by CD, for dense vectors or one-dimensional SparseIterate; a centered penalty is refused, even with an all-zero center. IndNonnegative() and an unweighted NormL1Nonneg(lambda) target the least-squares objective over x >= 0 (with lambda * sum(x) added for the latter) and are supported for a dense vector only, not for a SparseIterate; the starting vector must be nonnegative, and a negative entry is refused rather than projected. converged is a change test, so assess the returned point with an independent constrained KKT score. The cached residual and the reported minimum are specified in CD-05 and CD-09. Weights must be a matching Vector{T} satisfying the coefficient-range rules. A zero weight removes that coordinate's L1 term. For ElasticNet, the ridge level lambda2 applies to each coordinate. Its input and arithmetic rules are IN-03. Group penalties require matching partitions; matrix-response groups are the rows of the coefficient matrix, indexed through vec(B).

Square-root lasso requires an unscaled SqrtLeastSquaresLoss and unweighted NormL1(lambda) with lambda > 0. For the normalized square-root objective, use lambda = sqrt(n)*lambda_n in this unnormalized interface. For a positive minimum, converged=true proves a relative objective error of at most 1e-4. The certificate bound is rounded upward to the working type T for gap, so its stored Float32 value can be slightly above 1e-4. After an uncertified change-test stop, a bounded smoothing fallback can certify the stopped point or return a point with a proved lower objective. It uses the remaining maxpasses budget and the solver's order, momentum, RNG and tolerances; its passes count in the result and its random passes advance the borrowed RNG. A run that reaches maxpasses does not start this fallback. Recovery at exact fits is not guaranteed: a final uncertified result has converged=false, gap=NaN and a warning. See the bounded square-root fallback.

CD commits coefficients only after a completed run with a finite objective. An exception escaping solve! preserves the caller's starting coefficients, although a borrowed RNG may have advanced. After a successful sparse/group solve, obtain fresh active-coordinate/value views because compaction can change the storage.

Detailed rules:

  • Sparse storage and commit semantics.
  • Group steps, curvature and refusals.
  • Multi-response shapes and row groups.
  • Square-root steps and bounded certificate.

See solve! and the solver guide.

ProximalSolvers.ProximalGradientDescent — Type
ProximalGradientDescent(; ls=LineSearches.BackTracking(), normalized=false,
                         debias=0, preconditioner=:none)

Proximal gradient descent for least squares with NormL1 or ElasticNet (each optionally weighted), NormLinf, NormL2, GroupNormL2, unweighted NormL1Nonneg or IndNonnegative(). Vector regression uses dense Float32 or Float64 coefficients and same-type data. For a matrix response, use dense same-type X, Y and B with unweighted NormL1(lambda). Each iteration combines a smooth-loss gradient step with the penalty's proximal operator, using backtracking. Pass ProximalOptions as the fifth argument to solve! for stopping and tracing.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                ProximalGradientDescent())

converged is a computed stopping decision, not a coefficient-accuracy promise; see the stopping contract.

Extended help

ls must be LineSearches.BackTracking; custom line searches are unsupported. The compatibility keywords normalized=false, debias=0 and preconditioner=:none are accepted only at their defaults and are not stored. PGD also solves the graphical lasso with LogDetLoss(S) and finite, nonnegative, symmetric Matrix weights in NormL1(λ₀, Λ), where diagonal weights are permitted. Start from a same-type dense Float32 or Float64 SPD matrix. See matrix PGD for the supported options and the KKT stopping check.

The entrywise matrix lasso applies the penalty to every coefficient, including diagonal entries. See IN-10. The weights of an ElasticNet(lambda1, lambda2, w) scale only its L1 term; see IN-03. Weighted matrix regression penalties are deferred. PGD requires dense coefficients and refuses SparseIterate, BlockIterate and square-root loss. A group penalty must have the same parameter type as the data and groups partitioning the coefficients.

NormL2(lambda) penalizes the Euclidean norm of the whole coefficient vector. Use it on a dense vector with raw or positively scaled least squares. See the Euclidean-norm input contract and its stopping check.

PGD also fits sparse logistic regression with a raw LogisticLoss(y, X) (dense Matrix{Float64} design, binary Vector{Float64} response, no observation weights or offset) and NormL1, with or without penalty weights, on a Vector{Float64}. The loss is the sum over observations; a zero penalty weight leaves an intercept column unpenalized. Unsupported logistic inputs are refused when solve! is called, before any write. See the logistic input contract.

For nonnegative least squares, use IndNonnegative() or NormL1Nonneg(0). For nonnegative lasso, use unweighted NormL1Nonneg(lambda) with a positive level. Both require a nonnegative starting vector. Infeasible starts are refused before writes, and the proximal step preserves feasibility. The level must be finite, nonnegative and representable in the working type. Weighted NormL1Nonneg is unsupported, including an all-ones weight vector. PGD and CDSolver (least squares, a feasible dense Vector) accept the unweighted form. See the input contract.

A stopping proposal from the iterate, objective or gradient test must pass the applicable stationarity check. NormL1, ElasticNet, NormL2, GroupNormL2, NormL1Nonneg, and IndNonnegative() have KKT checks; the nonnegative case uses the constrained scores at positive and zero coefficients specified by STOP-16. Use IndBox or IndBallLinf for box constraints and IndBallL2 for a four-coefficient Euclidean ball with a same-type radius. These indicators require a feasible start and use the generic proximal-gradient check, as does NormLinf. Assess fits with an independent diagnostic, particularly for Float32 or ill-conditioned designs. An error in an iteration restores the last accepted coefficients and is rethrown.

  • Backtracking and numerical range limits.
  • Stopping criteria and result interpretation.

ProximalSolvers.AccProxGradDescent — Type
AccProxGradDescent(; β = 0.5, α = 0.9, preconditioner = :none)

Accelerated proximal gradient descent for dense Float32/Float64 least squares with NormL1 or ElasticNet (each with optional weights), NormLinf, NormL2 or GroupNormL2. A dense matrix response with dense same-type coefficients uses unweighted NormL1 on its entries. A raw LogisticLoss(y, X) with NormL1 on a Vector{Float64} is also supported (see below). APG extrapolates from previous accepted iterates, takes a backtracked proximal step, and restarts the step without momentum when it used momentum and the objective increased. Pass ProximalOptions as the fifth argument to solve!; the result and stopping interface are shared with PGD.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                AccProxGradDescent())

converged reports the computed stopping criterion, not coefficient accuracy; see the stopping contract.

Extended help

  • β=0.5: factor shrinking the step after a rejected trial; 0 < β < 1.
  • α=0.9: factor reducing curvature before each iteration; 0 < α <= 1. At α=1 this adjustment does not grow the step.
  • preconditioner=:none: only supported value; other choices are rejected.

Parameter bounds must also hold after conversion to the working type, and additional dimension bounds apply. The extrapolation weight is k/(k+3), counting from the start or last restart; this is not the textbook FISTA recurrence. A restart repeats the step without momentum. An error in backtracking restores the last accepted coefficients and is rethrown.

For least squares, the supported penalties are NormL1 and ElasticNet, each with optional weights (IN-03), NormLinf, NormL2 (IN-11) and a matching GroupNormL2{T} on dense coefficients. Box constraints use IndBox or IndBallLinf. Euclidean-ball constraints use IndBallL2 with four coefficients and a radius of the same type. These indicators require a feasible starting vector. Use ProximalGradientDescent, or CDSolver on a dense Vector, for IndNonnegative() and unweighted NormL1Nonneg; APG does not support those constrained penalties.

Sparse logistic regression takes a raw LogisticLoss(y, X) (dense Matrix{Float64} design, binary Vector{Float64} response, no observation weights or offset) with NormL1, with or without penalty weights, on a Vector{Float64}; a zero penalty weight leaves an intercept column unpenalized. The loss, coefficient and penalty rules are those of the gate of ProximalGradientDescent, and the dimension limits above also apply. The factor 1/4 of the logistic Hessian bound takes the place of the loss scale in the certified line-search test: a nonzero trial from the extrapolated point can be accepted only if the image bound is certified, after the guards in APG-08. The test does not use the local curvature, so a step can be shorter than a test on the loss value would allow. See the logistic input contract and APG-08.

A proposed stop is checked at the accepted point. The iteration's reported gradient-mapping residual is measured from the extrapolated point, so use the stopping documentation when interpreting it. The extra gradient for a proposed stop is included in grad_calls.

  • Extrapolation and restarts and dimension limits.
  • Certified local bound test and assumptions.
  • Shared stopping and exceptional exits.

ProximalSolvers.ProxNewton — Type
ProxNewton(; inner = CDSolver(order = :cyclic, momentum = false, relative = false, tol = 1e-11, maxpasses = 2000),
             maxiter = 100, tol = 1e-7)

Proximal Newton method for sparse logistic regression: the raw LogisticLoss(y, X) of ProximalBase, with a binary response, dense Float64 data and NormL1(lambda) or NormL1(lambda, w) on a dense Vector{Float64}, passed to solve!. The objective is the summed loss sum(log(1 + exp(eta_i)) - y_i * eta_i) with eta = X * b, plus the penalty; a column of ones with penalty weight zero is an unpenalized intercept. The call starts from the supplied coefficients and returns a ProxNewtonResults that shares them.

using ProximalBase, ProximalSolvers
X = [1.0 -1.0; 1.0 0.5; 1.0 1.5; 1.0 -0.5; 1.0 2.0; 1.0 -2.0]
y = [0.0, 1.0, 1.0, 0.0, 1.0, 1.0]
beta = zeros(2)
result = solve!(beta, LogisticLoss(y, X), NormL1(0.5, [0.0, 1.0]), ProxNewton())
result.converged, result.stop_reason

Each outer iteration forms a weighted least-squares model of the loss at the current point, with one weight per observation, and finds its composite minimizer approximately by cyclic coordinate descent. A search on the true objective then accepts a step along that direction. If the weighted model gives no accepted step, one model with the constant curvature 1/4 of the logistic loss is tried within the remaining pass budget. The result reports the objective, the largest ProximalBase KKT score kkt of the original problem at the returned point, the accepted iterations, all coordinate passes (including those of rejected trials) and a stop_reason: :converged, :maxiter or :stalled.

Keywords

  • inner: a CDSolver in cyclic order (order = :cyclic; a random order is refused). Its maxpasses is the budget of coordinate passes of one outer iteration, shared by the weighted model, its refinements and the fixed model. Its tol is an absolute threshold on the largest coefficient change of one full pass, in the units of the coefficients (relative is not used); it is the threshold of the first coordinate-descent run of each model, and it is lowered tenfold for each refinement. Zero turns the change test off, so that each run spends all its passes. Its momentum, rng and the other settings are not used.
  • maxiter = 100: the largest number of accepted outer iterations; 0 only tests the starting point.
  • tol = 1e-7: absolute tolerance on the largest ProximalBase KKT score of the original summed problem, in the units of the gradient of the loss. It is a computed residual, not a certificate: it does not bound the error in the coefficients, and where no minimizer exists (separated data, an unpenalized intercept) a small residual does not prove one does.

Memory: one n × p weighted design plus vectors of length n and p.

Extended help

  • Inputs, result and stop reasons.
  • Weighted and fixed models.
  • Inner solve, tolerances and pass budget.
  • Composite slope and objective search.
  • Stopping, mutation and failure boundary.

ProximalSolvers.LogisticADMM — Type
LogisticADMM(; ρ = 0.25, maxiter = 10_000, tol = 1e-7, abstol = 1e-8, reltol = 1e-6, abstol_dual = abstol,
               inner = CDSolver(order = :cyclic, momentum = false, relative = false, tol = 1e-8, maxpasses = 1000))

Alternating direction method of multipliers (ADMM) for sparse logistic regression: the raw LogisticLoss(y, X) of ProximalBase, with a binary response, dense Float64 data and NormL1(lambda) or NormL1(lambda, w) on a dense Vector{Float64}, passed to solve!. The objective is that of ProxNewton: the summed loss sum(log(1 + exp(eta_i)) - y_i * eta_i) with eta = X * b, plus the penalty; a column of ones with penalty weight zero is an unpenalized intercept. It returns a LogisticADMMResults that shares the caller's coefficients.

using ProximalBase, ProximalSolvers
X = [1.0 -1.0; 1.0 0.5; 1.0 1.5; 1.0 -0.5; 1.0 2.0; 1.0 -2.0]
y = [0.0, 1.0, 1.0, 0.0, 1.0, 1.0]
beta = zeros(2)
result = solve!(beta, LogisticLoss(y, X), NormL1(0.5, [0.0, 1.0]), LogisticADMM())
result.converged, result.stop_reason

The method splits the predictor from the coefficients with the constraint t = X * b and a scaled dual u with one entry per observation (not per coefficient, as in the consensus ADMMSolver). Each iteration approximately minimizes the penalty plus (ρ/2) * norm(X * b - t + u)^2 over b by warm-started cyclic coordinate descent within a pass budget, solves one scalar logistic proximal problem per observation for t, and updates u by X * b - t. The solve stops with converged = true when the primal residual norm(X * b - t), the dual residual ρ * norm(X' * (t - t_previous)) and the largest ProximalBase KKT score of the original problem at the returned coefficients are within their thresholds. That is a computed check of the returned point, not a certificate of the minimizer or of the accuracy of the coefficients. ADMM is not presumed to be faster than ProximalGradientDescent or ProxNewton on this problem; its iteration count depends on ρ, a tuning parameter.

solve!(b, f, g, LogisticADMM(); t = t0, u = u0) starts from a given predictor and dual (each a Vector{Float64} of length n); without them t = X * b and u = (σ(t) - y) / ρ. With this dual, an exact minimizer of the same objective and its own predictor are a fixed point of the ideal iteration. A warm start from another solver's solution or from a fit at another level can move (a computed solution can also coincide with an exact fixed point), and the number of iterations it takes depends on the fit. To restart with a different ρ, pass u * ρ_old / ρ_new: u is the scaled dual of the ρ it was computed with.

Extended help

Keywords

  • ρ = 0.25: the penalty of the augmented Lagrangian, in [1e-10, 1e10] after conversion to Float64. The default is the bound 1/4 on the curvature of the loss of one observation.
  • maxiter = 10_000: the largest number of completed iterations; 0 evaluates the starting point only.
  • tol = 1e-7: absolute tolerance on the largest ProximalBase KKT score of the original summed problem at the returned coefficients, in the units of the gradient of the loss. It is a computed residual, not a certificate: it does not bound the error in the coefficients, and where no minimizer exists (separated data, an unpenalized intercept) a small residual does not prove one does.
  • abstol = 1e-8, reltol = 1e-6: the primal threshold sqrt(n) * abstol + reltol * max(norm(X * b), norm(t)); abstol_dual = abstol with reltol: the dual threshold sqrt(p) * abstol_dual + reltol * norm(ρ * X' * u).
  • inner: a CDSolver in cyclic order with maxpasses >= 1 (any other value is refused). Its maxpasses is the budget of coordinate passes of the coefficient step of one iteration and its tol the first absolute threshold on the largest coefficient change of a pass, lowered tenfold, at most four times, while the step misses its forcing target. Its relative, momentum, rng and the other settings are not used.

Memory: vectors of length n and p; no n × p array beyond the borrowed X.

Contract

  • Inputs, result and stop reasons.
  • The coefficient step and its inner accuracy.
  • The scalar logistic proximal root and the dual update.
  • Residuals, stopping and certification.
  • Mutation and failure boundary.

ProximalSolvers.ADMMSolver — Type
ADMMSolver(; ρ=1.0, α=1.0, abstol=1e-6, reltol=1e-4, abstol_dual=abstol, adaptive=false)

Solve SqrNormL2(λ, c) + NormL1(τ) by scaled consensus ADMM on a dense Vector{Float32} or Vector{Float64} with a same-type center c. It also solves the lasso LeastSquaresLoss(y, X) + NormL1(τ) on dense Float64 data with n ≥ p (ADM-05). ρ is the positive penalty and α ∈ (0, 2) controls relaxation. The absolute and relative tolerances control the primal and dual residual tests. Set adaptive=true to rebalance the penalty between iterations.

With a dense Matrix{Float32} or Matrix{Float64} start, it applies to the graphical lasso LogDetLoss(S) + NormL1(λ₀, Λ) under the input rules of ADM-04, which include finite, nonnegative, exactly symmetric full matrix weights Λ of the same type, a fixed ρ, a stored α equal to 1 and adaptive = false. Diagonal weights may be positive.

See the ADMM contract for the supported inputs and iteration rules, and ADM-04 for the graphical lasso.

ProximalSolvers.solve! — Function
solve!(x, f, g, CDSolver())
solve!(x, f, g, ProximalGradientDescent(), options=ProximalOptions())
solve!(x, f, g, AccProxGradDescent(), options=ProximalOptions())
solve!(x::BlockIterate, f, g::GroupNormL2, CDSolver())

Minimize a supported penalized regression objective, overwriting x, and return a result whose minimizer is that coefficient storage. Use matching Float32/Float64 data and coefficients. CD additionally accepts sparse/group iterate storage and row-group matrix-response problems. PGD and APG accept entrywise matrix-response lasso with unweighted NormL1 under IN-10. Choose a method and penalty from the support matrix.

using ProximalBase, ProximalSolvers
X = [1.0 0.0; 0.0 2.0; 0.0 0.0]
y = [2.0, -2.0, 0.5]
beta = zeros(2)
result = solve!(beta, (1/3)*LeastSquaresLoss(y, X), NormL1(0.1),
                CDSolver(order=:cyclic, momentum=false))
saved_beta = copy(result.minimizer)

The meaning of converged depends on the method and loss; see result semantics.

Extended help

LeastSquaresLoss is half the sum of squared residuals. Multiply by 1/n for the conventional normalized lasso. One supported positive scalar loss wrapper is accepted. Penalty levels and weights must meet the relevant input rules. A zero weight removes the weighted term for its coefficient or group. For ElasticNet, the ridge term still applies to every coefficient.

Do not modify data during a solve, or alias x with the data, penalty weights or other disallowed mutable storage. Results share x; copying the result object alone does not preserve earlier coefficients.

An exception escaping a CD solve leaves the caller's original coefficients unchanged; a completed finite run, including a pass-limit outcome, commits its final point. PGD/APG iteration errors restore the last accepted point and rethrow. Internal counters have no transaction guarantee. A borrowed CD RNG may have advanced when a numerical failure occurs during a pass. After a successful sparse/group solve, reacquire active-coordinate/value views because its active storage can change.

Ridge via uncentered SqrNormL2(lambda) is supported with least squares and CD on a dense vector or one-dimensional SparseIterate. Its penalty is (lambda/2) * sum(abs2, x); lambda must be finite, nonnegative and representable in the coefficient type. Centered penalties, including an all-zero center, and this penalty with PGD, APG, block/matrix coefficients or square-root loss are refused. See supported inputs.

Group CD requires a BlockIterate with the penalty's ordered groups; group PGD/APG require a same-type GroupNormL2{T} and dense coefficients. PGD and APG accept NormL2(lambda) for least squares with a dense coefficient vector. Square-root lasso is available only with CD, an unscaled loss and an unweighted positive L1 level; its successful stopping flag requires a certificate.

Use IndNonnegative() or NormL1Nonneg(0) for nonnegative least squares and unweighted NormL1Nonneg(lambda) for nonnegative lasso. These penalties are accepted by PGD and by CDSolver on a dense Vector, with dense same-type least-squares data and a nonnegative starting vector; APG, and CD on a SparseIterate, refuse them. An infeasible start is refused before writes. PGD's stopping check uses the constrained KKT residual and the lasso's symmetric gradient scale. CDSolver reports convergence on its change test, so its converged flag is not a KKT check; assess its point with an independent constrained KKT score. See inputs, PGD's stopping check and CD's change test.

  • Supported inputs, dimensions and scalar parameters.
  • Aliasing and borrowed input requirements.
  • Results, mutations and numerical failures.
  • Sparse iterate storage and commitment.
  • Group steps and private storage.

solve!(x, f, g, AccProxGradDescent(), options=ProximalOptions())

Minimize the same least-squares lasso, elastic net, NormLinf or NormL2 problem as ProximalGradientDescent with accelerated proximal gradient descent, overwriting dense Vector{T} coefficients with T = Float32 or Float64. A dense matrix response uses same-type dense matrix coefficients and unweighted NormL1 under IN-10.

Extended help

For least squares, the options and their validation are those of ProximalGradientDescent (see ProximalOptions), and the penalties are those listed for AccProxGradDescent; IndNonnegative() and unweighted NormL1Nonneg on dense vector coefficients are accepted by ProximalGradientDescent and CDSolver only. The listed penalties, a weighted ElasticNet and a GroupNormL2 included, apply to dense vector coefficients with least squares, and the group stopping check is described under ProximalGradientDescent. In addition β and α must satisfy their bounds after conversion to T, and the dimensions must satisfy max(n, p) + 4 < 1/(4 eps(T)) and n p + 3 < 1/(4 eps(Float64)) (for Float32, max(n, p) < 2,097,148), which the rounding-error bounds of the line search need for one response. For K response columns, the first bound uses max(nK, pK). See APG-07.

A raw LogisticLoss(y, X) with NormL1 on a Vector{Float64} is solved for the summed logistic objective of IN-09, which gives the input rules and the order of refusals shared with PGD. The factors β and α and the dimension limits for one response above also apply, and the line search is that of APG-08.

Every refusal of an input, option or method setting happens before x is modified. A step error restores the last accepted x and rethrows, without a transaction guarantee for internal counters. The result shares x.

solve!(z, f, g, method::ADMMSolver, options=ProximalOptions(); u=nothing)

Minimize f(z) + g(z) and store the returned consensus iterate in z. Use f = SqrNormL2(λ, c) with a finite positive level and an unweighted g = NormL1(τ) with a finite nonnegative level. The levels must be exactly representable in the common Float32 or Float64 element type of z and c. The initial scaled dual is zero by default. Pass an independent, same-type buffer as u to start from its entries. Caller buffers are committed on normal return. Pass the returned iterate, scaled dual and penalty together to restart a solve. See ADMMResults and the ADMM input and result contract. A dense Matrix{Float32} or Matrix{Float64} start selects the graphical lasso of ADM-04; Extended help summarizes its inputs.

A raw f = LeastSquaresLoss(y, X) with dense Float64 y and X of size n × p, n ≥ p ≥ 1, a Float64 start of length p and an unweighted g = NormL1(τ) solves the lasso. It reuses the cached decomposition of f and borrows y, X and the scratch of f, which must not overlap z or u. A wide design (n < p) is refused with an ArgumentError. See ADM-05.

Extended help

In summary, the graphical lasso uses one element type T, Float32 or Float64, for z, S and Λ: an exactly symmetric Matrix{T} start whose Cholesky factorization succeeds in T, f = LogDetLoss(S) with weight one, and g = NormL1(λ₀, Λ) with finite, nonnegative, exactly symmetric full Matrix{T} weights and a finite, nonnegative level exactly representable in T. Diagonal weights may be positive. See ADM-04 for the complete conditions, including the method settings.

ProximalSolvers.ProximalOptions — Type
ProximalOptions(; maxiter=200, ftol=1e-6, xtol=1e-8, gradtol=1e-5,
  allow_f_increases=false, store_trace=false, show_trace=false,
  extended_trace=false, print_every=1, callback=nothing, time_limit=Inf,
  f_calls_limit=0, grad_calls_limit=0, prox_calls_limit=0, gaptol=0, gapevery=10)

Options for ProximalGradientDescent and AccProxGradDescent. Configure iteration limits, stopping tolerances, traces and callbacks. Any one of the iterate, objective or gradient tests can propose a stop; the applicable computed stationarity check must also pass. Defaults are suitable for an initial exploratory solve, without promising a particular coefficient accuracy.

using ProximalSolvers
options = ProximalOptions(maxiter=2000, ftol=1e-13, xtol=1e-11,
                         gradtol=1e-9, store_trace=true)

A successful stopping flag is not an exact optimality certificate; see the stopping rules.

ADMMSolver uses maxiter, prox_calls_limit and time_limit. It checks the limits before starting the next pair of proximal calls. See the ADMM options contract. For matrix PGD, see the accepted settings and limit checks.

Keywords

  • maxiter=200: iteration limit.
  • ftol=1e-6: nonnegative objective-change tolerance; 0 disables that test.
  • xtol=1e-8: iterate-change tolerance.
  • gradtol=1e-5: gradient/proximal-residual tolerance; the final stationarity check has its own working-precision floor.
  • allow_f_increases=false: stop on a computed objective increase; true removes that exit without certifying the result.
  • store_trace=false: retain iteration states in the returned trace.
  • show_trace=false: print the iteration trace.
  • extended_trace=false: include copied iterates and gradients in trace metadata.
  • print_every=1: display and callback cadence.
  • callback=nothing: optional callback; receives the stored trace when tracing is enabled, otherwise the current state, and returning true requests a stop.
  • time_limit=Inf: elapsed-time limit in seconds.
  • f_calls_limit=0, grad_calls_limit=0, prox_calls_limit=0: limits on smooth-loss, gradient and proximal calls, respectively; zero means unlimited. Limits are checked after complete iterations, so a count can exceed its limit by the work of one iteration.
  • gaptol=0: reserved dual-gap stopping target; only 0 is accepted.
  • gapevery=10: reserved interval between dual-gap checks; it must be positive but has no effect. Neither gap-related argument is stored.

Extended help

For NormL1, ElasticNet and GroupNormL2, a proposed stop is checked against the applicable computed KKT residual; NormLinf uses a proximal-gradient mapping check. Neither certifies coefficient error. Check optimality independently when the accuracy matters. These options do not configure coordinate descent: CDSolver accepts unweighted NormL1(lambda), weighted NormL1(lambda, w), ElasticNet(lambda1, lambda2) with or without weights w, and uncentered SqrNormL2(lambda) for dense or one-dimensional SparseIterate least-squares problems and stops by its change test. On a dense vector, CDSolver also accepts unweighted NormL1Nonneg and IndNonnegative(), with the same change test for converged.

For dense PGD with unweighted NormL1Nonneg(lambda) or IndNonnegative() (with lambda = 0), the KKT score is abs(grad[j] + T(lambda)) at a positive coefficient and max(-(grad[j] + T(lambda)), 0) at zero. The check uses the scale max(T(lambda), s * norm(X'y, Inf)) and tolerance floor 64eps(T); the complete threshold guards are in STOP-16. An infeasible starting point is refused before writes.

With ftol=0, an unchanged accepted iterate does not by itself count as convergence. Float32 PGD can instead report stagnated=true and converged=false under the documented stagnation condition. An objective increase, an iteration/call limit and convergence are separate conditions; inspect the individual result flags rather than inferring one from another.

The display label |g(x)| denotes an internal stopping residual, not the value of the supplied penalty. Data and iterate buffers keep their working type; Float64 tolerances or diagnostics do not increase Float32 coefficient accuracy.

ProximalSolvers.ProxNewtonResults — Type
ProxNewtonResults

Result of ProxNewton, sharing the caller's coefficient vector as minimizer. The fields are:

  • minimum: the original summed objective (loss plus penalty) at the returned point;
  • kkt: the largest ProximalBase KKT score of that problem at the returned point, formed from a fresh gradient;
  • tolerance: the tol of the solver;
  • iterations: the accepted outer iterations;
  • passes: all coordinate passes, including those of a model whose step the objective search then rejected;
  • converged: whether kkt is finite and at most tolerance, the computed check of the returned point;
  • stop_reason: :converged; :maxiter, the iteration budget was spent before convergence; or :stalled, no direction with a negative composite slope was accepted by the search (no pass budget, an exhausted search, or a step that rounds to no change).

A small kkt is a computed residual, not a certificate of the minimizer or of the accuracy of the coefficients. A converged = false result returns the last accepted point. The accessors minimizer, minimum, iterations and converged read the fields of the same names. See the result contract.

ProximalSolvers.LogisticADMMResults — Type
LogisticADMMResults

Result of LogisticADMM, sharing the caller's coefficient vector as minimizer. It is a type of its own, not an ADMMResults: its predictor t and dual u have one entry per observation. The main fields are:

  • minimum: the original summed objective (loss plus penalty) at the returned coefficients;
  • kkt: the largest ProximalBase KKT score of that problem at the returned coefficients, from a gradient formed there;
  • tolerance: the tol of the solver;
  • iterations: the completed iterations;
  • t, u: the returned predictor and scaled dual, each the caller's vector when one was passed to solve! (left with its entries when no iteration completed), and a new vector otherwise; ρ: the penalty of the solver;
  • converged: whether the last completed iteration passed the primal and dual residual tests and kkt is at most tolerance;
  • stop_reason: :converged; :maxiter, the iteration budget was spent (also for maxiter = 0); :stalled, an iteration left b, t and the working dual w = ρ u unchanged in every bit without converging; or :prox_failed, a scalar root failed (a nonfinite argument or the step budget) and that iteration was discarded.

A small kkt is a computed residual, not a certificate of the minimizer or of the accuracy of the coefficients. A converged = false result returns the last completed iteration. The accessors minimizer, minimum, iterations and converged read the fields of the same names.

Extended help

The diagnostics and work counters are:

  • r_norm, s_norm: the primal residual norm(X * b - t) and the dual residual ρ * norm(X' * (t - t_previous)) of the last completed iteration, and eps_pri, eps_dual their thresholds; all four are NaN when no iteration completed;
  • inner_kkt, inner_met: the KKT score of the coefficient step of the last completed iteration, formed from a fresh product at its coefficients, and whether it met its forcing target (NaN and false when no iteration completed);
  • dual_kkt: the largest ProximalBase KKT score of 0 ∈ ∂g(b) + ρ X' u at the returned b and u, evaluated in Float64 from the fresh product X' * (ρ .* u) (the scaled dual is formed first). It can be Inf or NaN, without an error, when terms or partial sums of that product overflow, also where the exact sum is representable or zero, and subnormal rounding of an entry ρ * u[i] can distort its contribution, upward or downward, or remove it when the entry rounds to zero;
  • predictor_residual: the largest entry of abs.(σ.(t) .- y .- ρ .* u) at the returned t and u; these two are formed from the returned values, while the residuals, thresholds and inner score are those of the last completed iteration;
  • passes: all coordinate passes of the coefficient steps, including those of an iteration discarded by :prox_failed; root_iterations: all steps of the scalar roots, counted in the same way.

See the result contract.

ProximalSolvers.ADMMResults — Type
ADMMResults

The result of solve! with an ADMMSolver. minimizer aliases the caller's vector or matrix and minimum is the objective there. iterations counts completed iterations, with two proximal calls each in prox_calls.

r_norm, s_norm, eps_pri and eps_dual describe the final residual tests. ProximalSolvers.OptimizationResults — Type
OptimizationResults

Result from plain or accelerated proximal gradient descent. minimizer aliases the caller's coefficient array. minimum is the reported objective there. iterations counts steps. converged means that a stopping proposal passed the applicable computed stationarity check. Extended help

Fields to inspect

  • method, minimizer, minimum: solver, shared coefficients and objective.
  • iterations, iteration_converged: work completed and whether maxiter was reached.
  • converged, x_converged, f_converged, grad_converged: the final stopping flags after the stationarity check; the last three are all false when it fails.
  • x_tol, f_tol, g_tol, x_residual, f_residual, g_residual: thresholds and reported diagnostics, defined precisely by the stopping contract.

ProximalSolvers.LineSearches.BackTracking — Type
BackTracking(; α = 0.9, β = 0.5, Lexact = Inf)

Backtracking settings for ProximalGradientDescent. The step size is 1/L; each iteration initially replaces L by α*L, and rejected trials raise it using the local curvature estimate and β. The object stores settings only and can be shared between solves; iteration bookkeeping belongs to the solver state.

using ProximalSolvers
ls = ProximalSolvers.LineSearches.BackTracking(α=0.9, β=0.5)
method = ProximalGradientDescent(ls=ls)

Step acceptance does not certify the returned optimum; see the line-search contract.

Extended help

The reference algorithm is TFOCS's private/tfocs_backtrack.m.

  • α=0.9: curvature reduction before an iteration; requires 0 < α <= 1.
  • β=0.5: raises curvature after a rejection, shrinking the step; requires 0 < β < 1.
  • Lexact=Inf: positive cap used by the curvature-estimate retry update.

The search starts with function-value estimates and can switch to gradient estimates when values are too close to compare. The least-squares implementation can recheck a rejected trial using its computed curvature. A trial with a nonfinite image or value is not accepted. Certain overflowing step norms are rescaled, but the implementation does not recover every underflow, cancellation or nonfinite intermediate.

These checks do not supply a general rounding certificate. A line-search error is propagated by solve! after restoring the last accepted coefficient vector. The precise update formulas, recheck exceptions and range limitations are in LS-01.
