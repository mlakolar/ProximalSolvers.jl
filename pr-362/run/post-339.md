**Cross-reference from the helper audit #353: an optional cleanup that can travel with the next change here**

The Stage 0 audit of #353 found that `_sqnorm!` (`src/cd/leastsquares.jl`) is a second sum-of-squares algorithm beside the cold branch of `_column_dot`, and that it can be deleted: `coordinate_scale` can read the curvature cache, which production fills before the call, and `_singleton_curvature` can use `sum(abs2, view(X, :, j))`. That is recommendation R3 of the report ([part 4](https://github.com/mlakolar/ProximalSolvers.jl/issues/353#issuecomment-6968386639); about 11 executable lines).

The maintainer **deferred it to this issue** ([decisions](https://github.com/mlakolar/ProximalSolvers.jl/issues/353#issuecomment-6969675059)) instead of doing it under #353, for reasons the audit measured: it is not bit-identical (the curvature bound and the minimizer move in the last bits in 94 to 97 % of singleton-group solves, with `converged` and an independent KKT residual unchanged at ordinary tolerances; at a Float32 tolerance below `eps(Float32)` two solves changed their pass counts at stagnation), it edits twelve test sites, and a direct `coordinate_scale` call on a cold cache needs a one-line fill. These are easier to absorb in a PR that already changes the group curvature code and its tests. In the audit's runs the deletion also made the preparation of singleton-group solves faster (geometric mean 0.77 of master on Julia 1.13, 0.85 to 0.89 on 1.10), and the majorization margin held for every summation order tried.

This is accompanying cleanup, **not a requirement for closing this issue**: if the curvature work here does not touch `_singleton_curvature` or `coordinate_scale`, `_sqnorm!` can simply stay. The evidence (the prototype patch `experiments/x2/x3.patch`, the group-solve comparison `x3_group*`, the edited test copies) is on the branch `archive/issue-353-evidence-r3`.
